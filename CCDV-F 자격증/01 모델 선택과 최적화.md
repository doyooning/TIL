# D5. 모델 선택과 최적화 (16.8%)

> 세부: LLM 기초 5.2% / 기술 기초 6.1% / 모델 선택·트레이드오프 2.7% / 비용·토큰 관리 2.8%

## 1. LLM / 토큰 기초

- **토큰**: 모델이 처리하는 텍스트 조각. 영어 기준 대략 **1토큰 ≈ 4자 ≈ 0.75단어**
- **컨텍스트 윈도우**: 한 요청에서 모델이 볼 수 있는 입력+출력 토큰의 총량. 요청마다 전체 대화 기록이 다시 전송되므로 턴이 쌓이면 입력 토큰이 누적된다
- **토크나이저 변경(중요)**: Claude 4.7 이후 모델(및 Fable/Mythos 계열)은 **새 토크나이저**를 사용해 같은 텍스트가 약 **30% 더 많은 토큰**으로 계산된다. 이전 모델에서 잰 토큰 수를 재사용해 비용·컨텍스트 적합성을 추정하면 안 된다
- **적응형 사고(adaptive thinking)**: 모델이 얼마나 생각할지 스스로 정하고 `effort`로 조정. 과거의 `thinking: {type:"enabled", budget_tokens:N}`(extended thinking)은 4.5 이하 모델의 방식
- **effort**: `low`/`medium`/`high`/`xhigh`/`max`. 응답당 추론 깊이 ↔ 비용·지연 시간의 트레이드오프. **extended thinking과는 별개 기능**

## 2. 현재 모델 라인업 (2026-09 기준)

| | Claude Fable 5.1 | Claude Opus 5.5 | Claude Sonnet 5 | Claude Haiku 4.5 |
| --- | --- | --- | --- | --- |
| 성격 | 까다로운 추론·장기 에이전트 작업 | 장기 실행 에이전틱 코딩·지식 작업 | 속도와 지능의 최적 조합 | 가장 빠르고 near-frontier |
| API ID | `claude-fable-5-1` | `claude-opus-5-5` | `claude-sonnet-5` | `claude-haiku-4-5-20251001` |
| 지연 시간 | 느림 | 보통 | 빠름 | 가장 빠름 |
| 가격(입력/출력 MTok) | $10 / $50 | $4 / $20 | $2 / $10 | $1 / $5 |
| Thinking | Adaptive (항상 on) | Adaptive (항상 on) | Adaptive | Extended |
| 기본 effort | `high` | `medium` | `high` | 미지원 |
| 컨텍스트 윈도우 | **1M** | **1M** | **1M** | 200K |
| 최대 출력 | 128K | 128K | 128K | 64K |
| 지식 기준일 | 2026-06 | 2026-06 | 2026-01 | 2025-02 |

- 어떤 모델을 쓸지 모르겠으면 **대부분의 워크로드는 Claude Opus 5.5로 시작**. Opus 5.5를 더 높은 effort로 돌려도 eval이 기대에 못 미치면 Fable 5.1
- 현재 모든 모델이 **텍스트·이미지 입력, 텍스트 출력, 다국어, 비전, 도구 사용**을 지원한다
- 모델 ID는 모두 **고정 스냅샷**이다(4.6 세대 이후의 날짜 없는 ID 포함). 4.6 이전 모델의 별칭은 날짜 붙은 ID를 가리키는 편의 포인터
- **Models API**(`GET /v1/models`)로 `max_input_tokens`, `max_tokens`, `capabilities`를 프로그래밍 방식으로 조회할 수 있다
- 배치 API에서는 `output-300k-2026-03-24` 베타 헤더로 Opus 5.5/5/4.8/4.7/4.6, Sonnet 5/4.6의 `max_tokens`를 **300k**까지 올릴 수 있다

## 3. 모델 선택 기준

| 상황 | 선택 |
| --- | --- |
| 단순·고빈도 작업(분류, 스크리닝, 추출) | **Haiku** |
| 대부분의 프로덕션 워크로드 | **Sonnet** |
| 복잡한 에이전틱 코딩·지식 작업 | **Opus** |
| 최고 난도의 장기 추론 | **Fable** |
| 복잡한 도구·모호한 쿼리 | 최신 Opus (누락 파라미터를 되묻는 경향이 강함) |
| 간단한 도구 | Haiku (단, **누락 파라미터를 추론해 채울 수 있음**에 주의) |

> "성능이 부족하다"의 해법이 항상 프롬프트 엔지니어링은 아니다. **지연 시간과 비용은 모델 교체로 푸는 게 나은 경우가 많다.**

## 4. 가격 구조

### 기본 요금 (USD / MTok)

| 모델 | 입력 | 5분 캐시 쓰기 | 1시간 캐시 쓰기 | 캐시 읽기 | 출력 |
| --- | --- | --- | --- | --- | --- |
| Fable 5.1 / Mythos 5.1 | $10 | $12.50 | $20 | **$0.25** (0.025x) | $50 |
| Opus 5.5 | $4 | $5 | $8 | **$0.20** (0.05x) | $20 |
| Opus 5 / 4.8 / 4.7 / 4.6 / 4.5 | $5 | $6.25 | $10 | $0.50 (0.1x) | $25 |
| Sonnet 5 | $2 | $2.50 | $4 | $0.20 | $10 |
| Sonnet 4.6 / 4.5 | $3 | $3.75 | $6 | $0.30 | $15 |
| Haiku 4.5 | $1 | $1.25 | $2 | $0.10 | $5 |

### 가격 수정자 (중첩 적용)

| 수정자 | 배수 |
| --- | --- |
| 5분 캐시 쓰기 | 기본 입력의 **1.25x** |
| 1시간 캐시 쓰기 | 기본 입력의 **2x** |
| 캐시 읽기(히트) | 기본 입력의 **0.1x** (Fable/Mythos 5.1은 0.025x, Opus 5.5는 0.05x) |
| **Batch API** | 입력·출력 **50% 할인** |
| 데이터 레지던시 `inference_geo: "us"` | **1.1x** (4.6 이후 모델) |
| Fast mode (Opus 5.5/5/4.8) | Opus 5.5 = $8/$40, Opus 5·4.8 = $10/$50. **배치와 병용 불가** |

> **손익분기**: 캐시 히트가 기본 입력의 10%이므로 5분 캐시(1.25x 쓰기)는 **1회 읽기 후**, 1시간 캐시(2x 쓰기)는 **2회 읽기 후** 이득이 난다.

### 긴 컨텍스트
Claude 4.6 이후 모델은 **1M 토큰 컨텍스트를 표준 가격으로 포함**한다. 900k 토큰 요청도 9k 토큰 요청과 토큰당 요율이 같다.

### 도구 사용 추가 비용
- `tools` 파라미터(이름·설명·스키마), `tool_use`/`tool_result` 블록
- **자동 삽입되는 도구 사용 시스템 프롬프트**: Opus 5 = `auto`/`none` 286 / `any`/`tool` 406토큰, Sonnet 5 = 354 / 474, Haiku 4.5 = 496 / 588
- 서버 도구 추가 요금: **웹 검색 = 1,000회당 $10**, 코드 실행 = 컨테이너-시간당 $0.05(월 1,550시간 무료, 웹 검색/가져오기와 함께 쓰면 무료), **웹 가져오기 = 추가 요금 없음**

### Managed Agents
토큰 요금 + **세션 런타임 시간당 $0.08**(`running` 상태만 계량). 배치 할인과 파트너 클라우드 가격은 적용되지 않는다.

### CCU (마켓플레이스 청구)
Claude Platform on AWS / Microsoft Foundry는 **Claude Consumption Unit**으로 청구한다. 토큰 사용량을 표준 요율로 USD 환산 → 할인 적용 → **CCU당 $0.01**로 변환. 100 CCU = $1.00.

## 5. 토큰 카운팅 API

```
POST /v1/messages/count_tokens
→ { "input_tokens": 14 }
```

| 항목 | 내용 |
| --- | --- |
| 지원 입력 | system, messages, tools(클라이언트 도구 + advisor), base64 이미지, base64 PDF, thinking 블록 |
| **미지원 → 400** | 서버 도구(advisor 제외), MCP 커넥터, `url`/`file` 소스의 image·document 블록 |
| 가격 | **무료** |
| 속도 제한(RPM) | Start 5,000 / Build 10,000 / Scale 20,000. **메시지 생성과 독립된 제한** |
| 정확도 | **추정치**. 시스템이 자동 추가한 토큰이 포함될 수 있으나 그 부분은 과금되지 않음 |
| 캐싱 | 토큰 카운팅은 캐싱 로직을 쓰지 않는다 |

**thinking 토큰 포함 규칙**: *현재* 어시스턴트 턴의 사고는 입력 토큰에 포함된다. *이전* 턴의 사고는 "모든 이전 턴을 유지하는 모델"에서만 포함된다.

## 6. 비용 최적화 전략

1. **적절한 모델 선택** — 단순 작업은 Haiku, 대부분은 Sonnet, 최고 난도만 Opus
2. **프롬프트 캐싱** — 반복되는 시스템 프롬프트·문서·도구 정의·대화 기록을 캐시 (→ [[05 프롬프트와 컨텍스트 엔지니어링]])
3. **배치 처리** — 시간에 민감하지 않은 작업은 Batch API로 50% 절감 (→ [[03 애플리케이션 설계와 통합]])
4. **effort 낮추기** — 파일 조회·단순 grep 수준 작업은 `effort: low`
5. **사용 패턴 모니터링** — Console의 Usage 페이지, Usage & Cost API
6. **컨텍스트 관리** — 오래된 도구 결과 지우기, 서브에이전트 위임

### 캐싱이 처리량에도 이득인 이유
**대부분의 모델에서 `cache_read_input_tokens`는 ITPM 속도 제한에 포함되지 않는다.** ITPM 2,000,000에 캐시 적중률 80%면 실질적으로 분당 총 10,000,000 입력 토큰을 처리할 수 있다. (예외: Claude Haiku 3.5는 캐시 읽기도 ITPM에 포함)

## 7. 지출 한도와 사용량 티어

| 사용량 티어 | 월간 지출 한도 |
| --- | --- |
| Start | $500 |
| Build | $1,000 |
| Scale | $200,000 |
| Custom | 한도 없음(계약) |

- 조직은 사용 이력·계정 상태에 따라 **자동으로 티어 배치**되고, 사용이 쌓이면 상향된다
- 신규·이력이 적은 조직은 **Evaluation 티어**에서 표준보다 낮은 제한으로 시작
- 티어 지출 한도 도달 → **HTTP 429**, `error_code: enforced_spend_limit_reached`, `retry-after` 헤더 없음, 다음 달 1일 00:00 UTC까지 차단
- 스스로 설정한 지출 제한 초과 → **HTTP 400** `invalid_request_error`
- Console에서 워크스페이스별로 더 낮은 지출·속도 제한을 설정할 수 있다(기본 워크스페이스는 불가)
