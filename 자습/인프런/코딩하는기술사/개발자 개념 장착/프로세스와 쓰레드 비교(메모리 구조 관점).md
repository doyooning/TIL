# 쉬운 비유
###### 프로세스 
= 집
옆집이 무너져도 안전함
독립적인 공간
`독립적인 자원의 단위`

###### 쓰레드 
= 집에 사는 사람
거실, 주방을 함께 씀
자원을 공유함
`공간을 공유하되 각자 할 일을 한다`

**핵심**
###### 메모리 구조 비교
프로세스:
Code / Data / Heap / Stack 모두 따로 독립됨
프로세스끼리 소통하려면 IPC와 같은 복잡한 통신이 필요

쓰레드:
Code, Data, Heap 공유 영역
Stack만 따로 가짐
= 독립적인 함수 호출이 가능하다
= 독립적인 실행 흐름을 가질 수 있다

# 왜 쓰레드가 더 빠를까?
Context Switching(문맥 교환) 비용 때문

프로세스를 바꾸는 것은 집을 이사하는 것과 같음
짐 다 싸고, 트럭에 싣고, ... 이사 비용이 큼
= 주소 공간이 바뀌면서 캐시나 메모리 관리가 무겁고 느림

쓰레드를 바꾸는 것은 그냥 방 문 열고 거실로 나오는 것과 같은 수준
공유하는 자원은 그대로 두고 내 몸만 빠져나오면 됨

때문에 멀티프로세스보다 멀티쓰레드가 처리도 빠르고 자원의 소모도 훨씬 적음

# 이론 정리
### Q. 메모리 구조 관점에서 프로세스와 쓰레드를 비교해보세요.
1. 프로세스는 자원 할당의 단위, 쓰레드는 실행 흐름의 단위입니다.
2. 가장 큰 차이는 **메모리 공유 여부**입니다.
3. 쓰레드는 Code, Data, Heap을 공유하고 Stack만 따로 가집니다.
4. 그래서 쓰레드가 **문맥 교환 비용**이 훨씬 적습니다.

# 꼬리 질문

### Q. 멀티프로세스 vs 멀티쓰레드, 언제 무엇을 쓸까요?
프로세스는 실행 중인 프로그램 단위이고, 쓰레드는 프로세스 내부에서 실제 작업을 수행하는 실행 흐름입니다.

멀티프로세스는 각각 독립된 메모리 공간을 사용하기 때문에 한 프로세스에 문제가 발생해도 다른 프로세스에 영향을 주지 않는다는 장점이 있습니다. 대신 프로세스 간 통신(IPC) 비용이 크고 메모리 사용량도 많습니다.

멀티쓰레드는 하나의 프로세스 내에서 메모리를 공유하기 때문에 생성 비용이 적고 자원 사용이 효율적입니다. 하지만 공유 자원을 사용하기 때문에 동기화 문제가 발생할 수 있습니다.

따라서
- 안정성과 격리가 중요하면 멀티프로세스
- 성능과 자원 효율이 중요하면 멀티쓰레드
를 선택합니다.

**Q. Java 웹 서버는 왜 멀티쓰레드를 사용할까요?**
> 하나의 JVM 안에서 여러 요청을 동시에 처리할 수 있고, 프로세스를 계속 생성하는 비용이 없기 때문입니다.

### Q. 크롬 탭은 프로세스? 쓰레드?
크롬은 기본적으로 탭마다 별도의 프로세스를 사용하는 멀티프로세스 구조입니다.

예를 들어 탭 하나가 비정상 종료되더라도 다른 탭은 계속 사용할 수 있습니다.

다만 탭 내부에서는 렌더링, 네트워크 처리, 자바스크립트 실행 등을 위해 여러 쓰레드가 동작합니다.

즉,
- 탭 간 = 멀티프로세스
- 탭 내부 = 멀티쓰레드
구조라고 이해하고 있습니다.

**Q. 왜 굳이 탭마다 프로세스를 분리했을까요?**
> 한 탭에서 오류가 발생해도 전체 브라우저가 종료되지 않도록 안정성을 높이기 위해서입니다.

### Q. 쓰레드 동기화(Deadlock) 문제는 어떻게?
데드락은 두 개 이상의 쓰레드가 서로가 가진 자원을 기다리면서 무한 대기 상태에 빠지는 현상입니다.

예를 들어
- Thread A : Lock1 → Lock2 대기
- Thread B : Lock2 → Lock1 대기
상황이 발생하면 서로 기다리기만 하게 됩니다.

해결 방법은
1. 락 획득 순서를 통일한다.
2. 필요한 최소 범위만 동기화한다.
3. 타임아웃을 설정한다.
4. 가능하면 락 사용을 줄인다.
입니다.

실무에서는 가장 많이 사용하는 방법이 **락 순서를 일관되게 유지하는 것**입니다.

**Q. synchronized를 많이 쓰면 안 되는 이유는?**
> 동시에 접근 가능한 쓰레드 수가 줄어들어 성능이 저하될 수 있기 때문입니다.
