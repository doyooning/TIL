# 동시성 (Concurrency)
: **구조와 설계**의 문제

- 한 명의 요리사가 여러 작업을 빠르게 번갈아가며 처리하여 동시에 진행되는 것처럼 보이게 하는 것과 같음
- = `번갈아 처리(Switching)`
- **싱글 코어**에서도 타임 슬라이싱(Time Slicing) 기술을 통해 구현 가능
- 비유: 논리적으로 여러 일을 효율적으로 다루기 위한 구조적 설계

# 병렬성 (Parallelism)
: **실행과 자원**의 문제

- 두 명의 요리사가 각자의 조리 도구를 가지고 진짜 물리적으로 동시에 요리하는 것과 같음
- = `진짜 동시 실행(Simultaneous)`
- **멀티 코어** 환경에서 물리적인 하드웨어 자원을 사용하여 실제로 같은 시간에 여러 작업을 수행
- 비유: 하드웨어 자원을 활용하여 물리적으로 작업을 동시 실행하는 것

# 핵심 구분

|       | 동시성(Concurrency)                                      | 병렬성(Parallelism)                                 |
| ----- | ----------------------------------------------------- | ------------------------------------------------ |
| 핵심    | 설계, 구조(Structure)                                     | 실행, 자원(Execution)                                |
| 싱글 코어 | 가능                                                    | 불가능                                              |
| 개념    | 논리적                                                   | 물리적                                              |
| 사례    | 싱글 코어 멀티태스킹, <br>이벤트 루프 기반 서버(Node.js),<br>비동기 I/O 처리 | 멀티코어 CPU 연산 병렬처리, <br>GPU 병렬 연산, <br>비디오/이미지 랜더링 |


# 이론 정리
### Q. 동시성과 병렬성을 비교해보세요.
1. **동시성**은 여러 작업을 빠르게 번갈아 처리해 동시에 진행되는 것처럼 보이게 하는 **논리적** 개념입니다.
2. **병렬성**은 물리적인 멀티코어 환경에서 실제로 동시에 작업을 수행하는 **물리적** 개념입니다.
3. 결론적으로 **동시성은 구조**이고, **병렬성은 실행**입니다.

# 꼬리 질문

### Q. 싱글코어에서 동시성이 왜 필요한가?
동시성은 여러 작업을 동시에 처리하는 것처럼 보이게 만드는 개념입니다.

싱글코어에서는 실제로 한 순간에 하나의 작업만 수행할 수 있기 때문에 병렬 처리는 불가능합니다. 
하지만 CPU가 매우 빠르게 작업을 번갈아 수행하면서 여러 작업이 동시에 진행되는 것처럼 보이게 할 수 있습니다.

예를 들어 웹 서버가
- 사용자 A 요청 처리
- 사용자 B 요청 처리
- DB 응답 대기

를 순서대로만 처리하면 비효율적입니다.
DB 응답을 기다리는 동안 CPU는 놀게 되는데, 이 시간에 다른 요청을 처리하면 자원을 더 효율적으로 사용할 수 있습니다.
그래서 싱글코어 환경에서도 동시성이 필요합니다.

### Q. 병렬성이 무조건 빠를까?
반드시 그렇지는 않습니다.
병렬 처리를 위해서는 작업을 나누고 결과를 합치는 과정이 필요한데, 이 과정에서도 비용이 발생합니다.
작업의 크기가 작거나 쓰레드 생성 비용이 큰 경우에는 오히려 단일 쓰레드보다 느려질 수 있습니다.

또한 여러 쓰레드가 같은 자원에 접근하면 동기화 비용이 발생하기 때문에 성능 향상이 제한될 수 있습니다.
그래서 병렬성은 CPU 연산이 많고 서로 독립적인 작업일 때 가장 효과적입니다.

### 예시
좋은 경우
- 대용량 이미지 처리
- 영상 인코딩
- 머신러닝 연산

효과가 적은 경우
- 매우 짧은 연산
- 락 경쟁이 심한 작업

**Q. 그럼 코어가 8개면 무조건 8배 빨라지나요?**

> 아닙니다. 작업 분할 비용, 동기화 비용, I/O 대기 시간 등이 존재하기 때문에 실제 성능 향상은 그보다 작습니다.

### Q. 파이썬은 멀티코어 환경에서도 쓰레드 병렬 처리가 안 되는데?
파이썬의 기본 구현체인 CPython에는 GIL(Global Interpreter Lock)이라는 구조가 있습니다.
GIL 때문에 한 순간에 하나의 쓰레드만 Python 바이트코드를 실행할 수 있습니다.
그래서 멀티코어 CPU가 있어도 CPU 연산 작업에서는 여러 쓰레드가 동시에 실행되지 못합니다.

즉,
- 멀티쓰레드 = 동시성 가능
- CPU 병렬 처리 = 제한

이라는 특징이 있습니다.

**Q. CPU 연산을 병렬 처리하려면 어떻게 하나요?**
> multiprocessing을 사용해서 여러 프로세스를 생성합니다. 프로세스는 각각 독립적인 Python 인터프리터를 사용하기 때문에 여러 코어를 활용할 수 있습니다.
