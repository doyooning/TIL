# 성능 튜닝 전 고려사항
### 병목(Bottleneck) 찾기가 최우선
추측하지 말고 측정
Slow Query 등

### Trade-off 고려
은탄환은 없다
읽기가 빨라지면 쓰기가 느려질 수 있음

대표적인 예시:
인덱스는 읽기 성능은 높여주지만, 쓰기 성능은 떨어뜨림

### Read : Write 비율 고려
대부분의 서비스는 읽기가 8:2로 압도적, 읽기 최적화 효율이 좋음

# 모범 답안
### Q. 성능 최적화에 대해 읽기와 쓰기로 나누어 설명해보세요.
1. 읽기 성능은 웹에서는 CDN과 브라우저 캐시를 통해, 
   어플리케이션에서는 캐싱 전략을 세워 향상시킬 수 있고,
   데이터베이스에서는 인덱스 설계와 리플리케이션(복제)으로 읽기를 분산시켜 최적화할 수 있습니다.
2. 쓰기 성능은 어플리케이션에서는 비동기 큐를,
   데이터베이스에서는 샤딩과 배치 처리를 통해 부하를 분산시킬 수 있습니다.
3. 무엇보다 성능 튜닝 전 병목 지점을 파악하고, 읽기와 쓰기 비율에 따른 Trade-off를 고려해야 합니다.
