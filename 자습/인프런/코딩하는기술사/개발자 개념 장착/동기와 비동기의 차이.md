# 잘못된 이해
동기(Sync)니까 동시에,
비동기(Async)니까 따로?
-> 아님

## 어원 풀이
**동기(같을 동, 시기 기)**
= 시간(Timing)을 맞춘다
(앞 작업 끝 - 뒷 작업 시작)

**비동기(아닐 비)**
= 시간을 맞추지 않는다
(너는 너, 나는 나)


# 쉬운 비유
### 동기
= 줄 서서 대기
앞 사람 주문/제조 끝날 때까지 뒷 사람은 계속 대기
주로 Blocking

### 비동기
= 진동벨 대기
주문 넣고 진동벨을 받음
진동벨 가지고 다른 행동 가능
제조 완료되면 진동벨이 울림, 찾으러 감(Callback)
주로 Non-blocking

# 왜 비동기를 쓸까?
핵심 이유:
**I/O(디스크, 네트워크) 작업은 느리고, CPU는 빠르다**
(느린 작업을 기다리느라 비싼 CPU를 놀게 하지 않기 위해)

### 서버(Backend) 관점
동기: DB에서 데이터 찾을 때까지 다른 요청을 못받고 멈춤(비효율)

비동기: DB에 "찾아줘" 시켜놓고 그동안 다른 사용자 요청 처리

### UI(Frontend) 관점
동기: 서버 응답 올 때까지 화면이 얼어버림(Freezing)

비동기: 로딩 중에도 스크롤/클릭 가능(쾌적한 사용자 경험)

# 이론 정리
### Q. 동기와 비동기의 차이점을 서술하세요.
1. 동기는 요청을 보낸 후 결과가 나올 때까지 기다렸다가 다음 작업을 진행하는 방식입니다(결과를 직접 기다림).
2. 비동기는 요청 후 결과를 기다리지 않고 완료 시점에 콜백/이벤트 등으로 결과를 처리하는 방식입니다.
3. 주로 I/O 작업(네트워크, DB) 효율을 위해 비동기를 사용합니다.

# 꼬리 질문

### Q. Blocking과 Sync는 같은 개념인가?
아닙니다. 자주 같이 사용되지만 다른 개념입니다.

- Sync(동기): 결과를 언제 처리할 것인가에 대한 개념
    작업이 끝난 후 다음 작업 진행
- Blocking: 스레드가 멈춰서 기다리는가에 대한 개념
    작업 완료까지 실행 흐름이 정지

예를 들어:
- 동기 + 블로킹
    DB 조회 결과가 올 때까지 기다린 후 다음 코드 실행
- 비동기 + 논블로킹
    요청만 보내고 다른 작업 수행, 완료되면 콜백 실행

즉,
> Sync/Async는 "결과 처리 방식",  
> Blocking/Non-Blocking은 "대기 중 스레드 상태"를 의미합니다.

### Q. JS는 싱글 스레드인데 어떻게 비동기 처리를 하는가?
JavaScript 엔진 자체는 싱글 스레드입니다.
하지만 브라우저나 Node.js가 제공하는 기능을 활용해서 비동기 처리를 수행합니다.

동작 과정:
1. JS가 `setTimeout`, `fetch` 같은 비동기 작업 요청
2. 브라우저(Web API) 또는 Node.js가 해당 작업 수행
3. 작업 완료 시 Callback Queue에 등록
4. Event Loop가 Call Stack이 비었는지 확인
5. 비어 있으면 콜백 실행

예시:
```js
console.log("1");

setTimeout(() => {
  console.log("2");
}, 1000);
  
console.log("3");
```

실행 결과
```
1
3
2
```

왜냐하면 `setTimeout`은 브라우저에게 맡기고 바로 다음 코드를 실행하기 때문입니다.

면접 답변:
> JavaScript는 싱글 스레드지만 브라우저의 Web API와 Event Loop를 활용하여 비동기 작업을 처리합니다. 비동기 작업은 별도 환경에서 수행되고, 완료된 작업은 큐에 저장되었다가 Event Loop에 의해 실행됩니다.

### Q. 비동기 처리를 동기처럼 보이게 하는 문법은?
`async/await` 입니다.
예전에는 콜백 함수나 Promise 체인을 사용했습니다.
```js
fetch("/api")
	.then((res) => res.json())
    .then((data) => console.log(data));
```

`async/await` 사용 시:
```js
async function getData() {
	const response = await fetch("/api");
	const data = await response.json();
	
	console.log(data);
}
```

코드가 순차적으로 실행되는 것처럼 보여 가독성이 좋아집니다.
하지만 실제로는 비동기 방식입니다.

면접 답변:
> async/await는 Promise 기반 문법으로, 비동기 코드를 동기 코드처럼 읽기 쉽게 작성할 수 있게 해줍니다. 
> 다만 실제 동작은 비동기적으로 수행됩니다.

### Q. 비동기가 오히려 안좋은 상황도 있는가?
있습니다.
비동기는 무조건 좋은 것이 아니라 관리 비용이 존재합니다.

#### 1. 순서 보장이 중요한 경우
```
잔액 조회
→ 결제
→ 결제 내역 저장
```

이런 작업은 순서가 중요하므로 동기적으로 처리하는 것이 안전합니다.

#### 2. 코드 복잡도가 증가하는 경우
비동기 로직이 많아지면
예외 처리, 디버깅, 흐름 추적이 어려워질 수 있습니다.

#### 3. 작업량이 매우 적은 경우
단순 계산만 수행한다면 비동기 처리에 필요한
스케줄링, 컨텍스트 관리 오버헤드가 더 커질 수 있습니다.

#### 4. 데이터 정합성이 중요한 경우
여러 비동기 작업이 동시에 같은 데이터를 수정하면
Race Condition, 데이터 불일치 문제가 발생할 수 있습니다.

예시:
```
현재 재고: 1개
사용자 A 구매
사용자 B 구매
둘 다 동시에 재고 조회 → 1개
둘 다 구매 성공
```

따라서 락(Lock)이나 트랜잭션 같은 추가 제어가 필요합니다.
