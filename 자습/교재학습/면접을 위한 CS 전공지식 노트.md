**애플리케이션 계층**
서비스를 실질적으로 제공하는 층
FTP, HTTP, SSH, SMTP, DNS 등

**전송 계층**
송신자와 수신자를 연결하는 서비스 제공
데이터 전달 중계 역할
TCP, UDP

**TCP 연결 성립 과정**
: 3-way handshake로 신뢰성 보장

1) SYN 단계
	클라이언트의 ISN을 서버로 보냄

2) SYN + ACK 단계
	서버가 클라이언트의 SYN 수신, 서버의 ISN을 보냄
	승인번호로 클라이언트의 ISN + 1을 보냄

3) ACK 단계
	서버의 ISN + 1한 값인 승인번호를 담아 ACK를 서버에 보냄

- SYN : Synchronization, 연결 요청 플래그
- ACK : Acknowledgement, 응답 플래그
- ISN : Initial Sequence Numbers, 초기 네트워크 연결시 할당된 32비트 고유 시퀀스 번호

**TCP 연결 해제 과정**
: 4-way handshake

1) 클라이언트 -> 서버 FIN 전송
	클라이언트가 연결을 닫으려고 할 때 FIN으로 설정된 세그먼트를 보냄
	클라이언트는 FIN_WAIT_1 상태 돌입, 서버 응답 대기

2) 서버 -> 클라이언트 ACK 전송
	서버는 클라이언트로 ACK라는 승인 세그먼트를 보냄
	서버는 CLOSE_WAIT 상태 돌입
	클라이언트는 이 세그먼트를 받으면 FIN_WAIT_2 상태 돌입

3) 서버 -> 클라이언트 FIN 전송
	서버는 ACK 보내고 일정 시간 이후에 클라이언트에 FIN 세그먼트를 보냄

4) 클라이언트 -> 서버 ACK 전송
	클라이언트는 TIME_WAIT 상태 돌입, 다시 서버로 ACK를 보냄
	ACK를 받은 서버는 CLOSED 상태가 됨
	클라이언트는 어느 정도 시간 대기 후 연결 닫힘

###### Q. 왜 이렇게까지 하나요?
A. 일정 시간 후 닫는 이유는
1. 지연 패킷 대비
	패킷이 뒤늦게 도착하고 이를 처리하지 못하면 데이터 무결성 문제 발생
2. 두 장치 연결이 닫혔는지 확인
	서버가 LAST_ACK인 상태에서 닫히게 되면 다시 새로운 연결을 하려고 할 때 접속 오류 

- TIME_WAIT
	소켓이 바로 소멸되지 않고 일정 시간 유지되는 상태, 지연 패킷 등 문제 해결
	OS마다 조금씩 다르고 우분투는 60초, 윈도우는 4분

**인터넷 계층**
장치로부터 받은 네트워크 패킷을 IP 주소로 지정된 목적지로 전송하기 위해 사용
패킷 수신 상대를 지정하여 데이터 전달
상대가 제대로 받았는지에 대해 보장하지 않음(비연결형)
IP, ARP, ICMP 등

**링크 계층**
전선, 광섬유, 무선 등 실질적으로 데이터 전달, 장치 간 신호를 주고받는 '규칙'을 정하는 계층
- 물리 계층 : 유무선 LAN으로 0과 1로 이루어진 데이터를 보내는 계층
- 데이터링크 계층 : '이더넷 프레임'을 통해 에러 확인, 흐름 제어, 접근 제어 담당하는 계층

**유선LAN(IEEE802.3)**
전이중화(full duplex) 통신
: 양쪽 장치가 동시에 송수신 가능, 고속 이더넷의 원리

###### CSMA/CD
반이중화 통신 방식 중 하나
데이터를 '보낸 후' 충돌 발생시 일정 시간 이후 재전송

###### 유선LAN 케이블
: TP 케이블, 광섬유 케이블

**무선LAN(IEEE802.11)**
반이중화(half duplex) 통신
: 동시 통신 불가, 한 번에 한 방향만 통신

###### CSMA/CA
반이중화 통신 방식 중 하나
데이터를 보내기 전 일련의 과정을 기반으로 사전에 가능한 한 충돌을 방지

** 전이중화 통신은 양방향 통신이라 충돌 가능성이 없음

###### 무선LAN 주파수
2.4GHz : 장애물에 강함, 전파 간섭 잦음
5GHz : 사용 채널 수 많고 동시 사용 가능하여 상대적으로 깨끗한 전파 환경 구축 가능

**계층 간 데이터 송수신 과정**
송신 : 캡슐화
수신 : 비캡슐화

**캡슐화 과정**
상위 계층의 헤더/데이터를 하위 계층의 데이터 부분에 포함시키고,
해당 계층의 헤더를 삽입하는 과정
- 애플리케이션 -> 전송 : TCP(L4) 헤더 삽입 = 세그먼트화, 데이터그램화
- 전송 -> 인터넷 : IP(L3) 헤더 삽입 = 패킷화
- 인터넷 -> 링크 : 프레임 헤더, 프레임 트레일러 삽입 = 프레임화

**비캡슐화 과정**
하위 계층에서 상위 계층으로 가며 각 계층의 헤더 부분을 제거하는 과정
캡슐화 역순
최종적으로는 사용자에게 애플리케이션의 PDU인 메시지로 전달

**PDU(Protocol Data Unit)**
네트워크 계층 간 데이터 전달에서 한 덩어리 단위
- 헤더 : 제어 관련 정보
- 페이로드 : 데이터

계층마다 부르는 명칭이 다름
- 애플리케이션 계층 : 메시지
- 전송 계층 : 세그먼트(TCP), 데이터그램(UDP)
- 인터넷 계층 : 패킷
- 링크 계층 : 프레임(데이터링크 계층), 비트(물리 계층)
