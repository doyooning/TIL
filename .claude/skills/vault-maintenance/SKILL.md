# Vault 유지보수 스킬

이 Obsidian vault의 링크(MOC), README 목차, 태그를 주기적으로 정리하는 작업을 수행한다.
사용자가 "vault 정리", "MOC 정리", "README 정리", "태그 관리", "최근 문서 링크 관리" 등을 요청하면 이 절차를 따른다.

## 이 vault의 규칙 (중요 — 먼저 숙지)

- **MOC(허브 노트)는 폴더명과 동일한 파일명**을 가진다.
  - 예: `프로젝트/프로젝트.md`, `AI 기반 지능형 솔루션 개발 과정/AI 기반 지능형 솔루션 개발 과정.md`,
    `자습/자습.md`, `메모/메모.md`, `신세계I&C교육/신세계I&C교육.md`
  - 모든 MOC는 상단에 `#MOC` 태그를 가진다. `Glob **/*.md` 후 각 파일 1행이 `#MOC`인 것으로 식별 가능.
- **태그는 YAML frontmatter가 아니라 파일 최상단의 인라인 `#태그`** 방식이다. (예: 1행 `#KDT`, 2행 `#Spring`)
- MOC는 `## 소제목` (또는 하위 폴더는 `### 소제목`)으로 섹션을 나누고, 그 아래 `- [[노트 제목]]` 형식으로 링크한다.
- 파일명이 곧 링크 대상이다. Obsidian 위키링크는 확장자 없는 파일명만 쓴다: `[[Day 14]]`.

## 태그 컨벤션

- **출처/분류 태그 (노트마다 1개 권장)**: `#KDT`(부트캠프 강의), `#프로젝트`, `#신세계`, `#자습` 등. 폴더 성격에 맞춘다.
  - `AI 기반 지능형 솔루션 개발 과정/` 하위 **강의 노트**(RPA, 컴퓨터 비전, 보충 설명 등) → `#KDT`
  - `AI 기반 지능형 솔루션 개발 과정/자습 부록/` 하위 **자율 학습 노트**(ML 이론 등) → `#자습`
  - `프로젝트/` 하위 → `#프로젝트`
- **주제/기술 태그**: `#JS`, `#Java`, `#Spring`, `#DB`, `#MySQL`, `#AWS`, `#Linux` 등.
- **인라인 플래그 `#보충설명`**: 출처/주제 태그와 다르다. 본문 중간에 "추가 조사 필요"를 표시하는 후속작업 마커로, 파일 상단이 아니라 해당 문장 옆에 붙는다. 최상단 출처 태그 점검(4단계)과 혼동하지 말 것. 집계는 5단계에서 별도로 다룬다.
- 슬래시 계층 태그(`#Spring/JPA`)도 가능. 새 태그를 만들기 전에 기존 태그를 재사용할 수 있는지 먼저 확인한다.

## 작업 절차

### 1. 최근 변경된 노트 찾기

git 이력으로 최근 추가/수정된 `.md` 노트를 파악한다. 기본 범위는 **최근 7일** 또는 마지막 정리 이후.

```bash
git log --since="7 days ago" --name-only --pretty=format:"=== %h %s ==="
```

Windows/한글 파일명 때문에 Bash에서 경로가 깨져 보이면, **`Glob`으로 각 폴더의 실제 `.md` 목록을 직접 얻는 것을 신뢰**한다. git 로그는 "어느 폴더가 활발한지" 파악용으로만 쓰고, 대조는 Glob 결과로 한다.

### 2. MOC 링크 대조 및 보강

변경이 있었던 각 최상위 폴더에 대해:

1. `Glob 폴더명/**/*.md`로 실제 노트 목록을 얻는다 (MOC 파일 자신은 제외).
2. 해당 폴더의 MOC(`폴더명/폴더명.md`)를 읽어 이미 링크된 `[[...]]` 목록을 추출한다.
3. **MOC에 없는 노트**를 찾는다.
4. 빠진 노트를 하위 폴더 구조에 맞는 섹션(`##` / `###`)에 `- [[노트명]]`으로 추가한다.
   - 하위 폴더가 새로 생겼으면 그에 맞는 소제목 섹션을 만든다 (예: `### ML 이론`, `### 보충 설명`).
   - 섹션 순서와 기존 스타일을 유지한다.

MOC 링크 추가는 사용자 확인 없이 진행해도 되는 안전한 작업이다 (누락 보강일 뿐).

### 3. README 목차 동기화

루트의 `README.md`는 **최상위 폴더별 소개**를 담은 인덱스다. MOC가 폴더 내부를 관리한다면, README는 최상위 폴더 목록을 관리한다.

1. 실제 최상위 폴더 목록을 얻는다. `Glob */` 또는 디렉터리 나열.
   - **제외 대상**: `.claude`, `.git`, `.obsidian` 등 설정/숨김 폴더 (vault 콘텐츠가 아님).
2. `README.md`의 `## 목차` 앵커 링크 목록과 실제 폴더를 대조한다.
3. README에 없는 새 최상위 폴더가 있으면:
   - `## 목차`에 `- [폴더명](#앵커)` 항목 추가 (기존 순서·스타일 유지)
   - 본문에 `## 폴더명` 섹션과 한두 줄 소개 추가
4. 폴더가 사라졌는데 README에 남아 있으면 **임의 삭제하지 말고 보고**한다 (의도적 보관일 수 있음).

README 항목 추가는 안전한 보강 작업이라 확인 없이 진행해도 되지만, 새 폴더 소개 문구는 폴더 내용을 확인한 뒤 자연스럽게 작성한다.

### 4. 태그 점검

변경된(또는 새로 추가한) 노트들의 최상단 태그를 확인한다:

- **태그 누락**: 파일이 `#태그` 없이 `---`나 본문으로 시작하면, 폴더 성격에 맞는 **출처 태그**를 제안한다.
- **뒤 공백**: `#KDT ` 처럼 태그 뒤 공백이 있으면 정리 대상으로 표시.
- **불일치**: 같은 폴더 내 다른 노트와 출처 태그가 다르면 지적.

태그 **수정(추가/공백 제거)은 사용자에게 확인**을 받은 뒤 적용한다. 단순 보고만 요청받았으면 수정하지 않는다.
단, 폴더 규칙상 출처 태그가 **일의적으로 확정**되는 경우(예: 컴퓨터 비전 강의 노트 → `#KDT`)와 뒤 공백 제거는 판단 여지가 없으므로 적용 후 보고해도 된다.

### 5. 미해결 #보충설명 집계

`#보충설명`은 파일 최상단 출처 태그와 달리, **노트 본문 중간에 "추가 조사 필요"를 표시하는 인라인 플래그**다.
조사가 끝나면 사용자가 제거하는 **후속작업 대기열**이므로, 정리할 때마다 남은 항목을 집계해 리마인드한다.

- `Grep '#보충\s?설명'` 으로 전체 발생 위치(파일·라인·문맥)를 찾는다.
- 상시 대시보드인 `AI 기반 지능형 솔루션 개발 과정/보충설명 대시보드.md` 는 집계에서 **제외**한다.
- 이 태그는 **임의로 지우거나 수정하지 않는다.** 목록으로 리마인드만 하고, 해결은 사용자 몫이다.
- 공백이 들어간 `#보충 설명`(깨진 형태)을 발견하면 붙여쓰기(`#보충설명`)로 고칠 것을 제안한다.

### 6. 루트에 흩어진 첨부 이미지 정리

vault 루트에 `Pasted image 20260811195527.png` 같은 붙여넣기 이미지가 남아 있으면 `첨부사진/`으로 옮긴다.

**왜 생기나**: Obsidian의 첨부파일 기본 저장 위치가 "vault 루트"다.
`.obsidian/app.json`에 `attachmentFolderPath`가 없으면 붙여넣기한 이미지가 계속 루트에 쌓인다.

**대상**: vault 루트 **직속**의 이미지 파일 (`.png` `.jpg` `.jpeg` `.gif` `.webp` `.svg`).
루트의 `.md` 노트(`README.md`, `프로그래밍 학습 템플릿.md` 등)와 하위 폴더는 건드리지 않는다.

절차:

1. 루트 직속 이미지 목록을 얻는다.
   ```bash
   ls *.png *.jpg *.jpeg *.gif *.webp *.svg 2>/dev/null
   ```

2. **옮기기 전에 참조 형식을 확인한다.** 이게 안전 여부를 가른다.
   - 이 vault는 위키링크(`![[파일명.png]]`) 방식이다. 위키링크는 **파일명으로 해석**하므로 폴더가 바뀌어도 링크가 유지된다 → 이동해도 안전.
   - 그러나 경로형 마크다운 링크(`![](Pasted%20image....png)`)로 **로컬 상대경로**를 쓴 참조가 있으면 옮기는 순간 깨진다.
     ```bash
     grep -rn "](.*파일명" --include="*.md" .
     ```
     이런 참조가 있으면 **옮기지 말고 보고**한다. (`https://`로 시작하는 외부 URL 링크는 무관하니 무시)

3. **이름 충돌을 확인한다.** `첨부사진/`에 같은 이름이 이미 있으면 **덮어쓰지 말고 보고**한다.

4. 이동한다. vault가 git 저장소이므로 `git mv`를 쓰면 이력이 이어진다.
   ```bash
   git mv "Pasted image 20260811195527.png" "첨부사진/"
   ```

5. **참조하는 노트가 하나도 없는 고아 파일**도 함께 옮기되, 고아라는 사실을 보고에 남긴다.
   삭제 여부는 사용자가 판단할 몫이므로 **임의로 지우지 않는다**.
   ```bash
   grep -rn "파일명" --include="*.md" . | grep -v "^./.git/"
   ```

**어디에 넣나**: `첨부사진/` 바로 아래에 둔다.
`첨부사진/kafka`, `첨부사진/spring-security` 같은 주제별 하위 폴더는 사용자가 수동으로 분류해 둔 것이므로,
파일명만 보고 주제를 추측해서 넣지 않는다.

**재발 방지 (선택, 확인 후 적용)**: `.obsidian/app.json`에 아래를 넣으면 이후 붙여넣기가 바로 `첨부사진/`에 저장된다.
```json
"attachmentFolderPath": "첨부사진"
```
Obsidian 동작을 바꾸는 설정이므로 **사용자 확인을 받고** 적용한다. 적용하려면 Obsidian을 닫은 상태여야 한다.

### 7. 결과 보고

다음을 표/목록으로 간결히 보고한다:

- MOC별로 추가한 링크 (폴더 · 섹션 · 노트명)
- README 목차에 추가한 최상위 폴더 (있으면)
- 이미 최신이라 건드리지 않은 MOC/README
- 태그 이슈 목록 (누락/공백/불일치)과 제안
- 🖼️ 루트에서 `첨부사진/`으로 옮긴 이미지 (파일명 · 참조 노트 수, 고아면 표시)
- 옮기지 않고 보류한 이미지와 그 이유 (경로형 링크 참조 / 이름 충돌)
- 🔍 미해결 `#보충설명` 개수와 위치 (파일 · 라인)
- 다음에 확인하면 좋을 사항

## 주의사항

- 노트 **본문 내용은 수정하지 않는다.** MOC 링크 추가와 (확인된) 태그 라인 정리만 한다.
- 오래된 링크(파일이 삭제/이름변경되어 깨진 `[[...]]`)를 발견하면 임의 삭제하지 말고 보고한다.
- `첨부사진`, `Excalidraw`, `폰트` 등 노트가 아닌 자산 폴더는 MOC/README 대조 대상에서 제외한다.
  단 `첨부사진`은 6단계에서 **이미지를 옮겨 넣는 목적지**로 쓴다.
- 이미지 파일은 **옮기기만 한다.** 이름 변경이나 삭제는 하지 않는다.
- 실제 파일 목록은 항상 `Glob`을 신뢰한다 (Bash의 한글 경로 인코딩보다 정확).
