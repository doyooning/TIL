# EC2
###### 인스턴스 유형 선택시 유의사항
사양은 CPU랑 RAM
가장 일반적으로는 t3.medium 정도 설정하는 듯
vCPU 2, 8Gib

근데 OpenVidu처럼 조금 헤비한 프로젝트들은 해당 사양에서 조금 버거움
t3.large 정도 하면 괜찮게 돌아감

###### 디스크 볼륨
용량 관련은 EBS 설정
= 디스크 용량(볼륨)
보통 8 Gib 정도로 설정하는데 여러 docker 이미지 다운받다보면 확장이 필요할 수 있음

확장시에는 인스턴스 중지하고 볼륨 수정으로 늘려줌
OpenVidu같은 경우는 8 Gib로는 절대 안되고 일단 20 Gib으로 도전
(녹화 저장 때문에 용량 과다 사용)

###### Elastic IP 적용
탄력적 IP를 적용하면 
매번 서버 인스턴스 중지 - 재시작 - 바뀐 퍼블릭IP로 접속하는 과정을 하지 않아도 됨
항상 같은 IP를 사용

탄력적 IP는 인스턴스가 매핑이 되고 사용중일 때 오히려 과금이 안 되는 구조
인스턴스가 중지된 경우에는 요금 발생
그치만 귀찮은 과정이 확 줄어들게 됨

# RDS
###### Amazon RDS
완전관리형 관계형 데이터베이스
RDB를 손쉽게 운영하고 규모를 조정

EC2에 DB를 직접 설치해서 사용해도 되지만
DB는 웹/앱 서버랑 구분해서 운영하는 것이 관리 측면에서 좋음

인스턴스를 생성해서 DB를 사용함
그러나 사용자가 시스템에 직접 로그인은 불가
대신 관리를 AWS에서 해줌

RDS는 기본적으로 VPC 안에서 동작하며, 
기본적으로 public IP를 부여하지 않아 외부에서 접근 불가능
설정에 따라 public으로 오픈 가능
대신 로드밸런서 같이 DNS로만 접근이 가능

DB의 설정값들을 모아 그룹화한 파라미터 그룹(Paramater Group) 시스템 지원
이 DB 설정들을 모은 그룹을 각 DB 인스턴스에 적용시켜 DB의 설정값을 적용하는 시스템
직접 RDS 인스턴스 수정이 불가능 하기 때문에 우회적인 방법으로 설정값을 세팅하는 원리

###### 특징 및 기능
**관리 부담 감소**
- 사용 편의성
- 자동 소프트웨어 패치
- 모범 사례 권장 시스템

**확장성**
- 즉각적인 컴퓨팅 규모 조정
- 간편한 스토리지 규모 조정
- 읽기 전용 복제본 시스템

**가용성 및 내구성**
- 자동 백업
- 데이터베이스 스냅샷
- 다중 AZ 구성 배포
- 자동 호스트 교체

**보안**
- 저장 데이터 및 전송 데이터 암호화
- 네트워크 격리
- IAM 리소스 수준 권한

**관리 효율성**
- 모니터링 및 지표
- 이벤트 알림

**비용 효율성**
- 사용한 만큼만 비용 지불
- 예약 인스턴스
- 인스턴스 중지 및 시작
