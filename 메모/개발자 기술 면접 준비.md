### 어떻게 준비할까?
###### 1. 기술 내부 동작 파악
라이브러리 사용법 말고, 해당 기술이 JVM 메모리 구조나 운영체제 커널 I/O를 어떻게 활용하는지를 학습

###### 2. 수치 기반 의사결정 기록
"빨라졌다" (X)
"p99 응답 시간이 300ms에서 100ms로 단축되었다" (O) -> 구체적 성능 지표 제시

###### 3. 실패 사례를 복기
성공한 코드보다 왜 이 코드가 에러를 냈고,
어떤 로그를 분석해 해결했는지

면접은 지식의 양보다 태도의 깊이를 확인
직접 겪은 기술적 고민이 강력한 무기

### AI 시대 백엔드 필수 질문
###### 1. 프로젝트의 아키텍처를 설명해주세요.
기능 구현 자체는 안어렵다
면접관이 진짜 보고 싶은건 **설계의 이유**
: "왜 나눴는지?", "왜 이 기술을 선택했는지?", "트래픽이나 장애 상황을 어떻게 고려했는지?"

기술 선택에는 반드시 Trade-off가 존재
비즈니스 + 시스템 의도
: 비즈니스 요구사항 -> 기술 선택 -> 시스템 설계

###### 2. 아키텍처를 설계하면서 가장 어려웠던 점은 무엇이고 어떻게 해결했나요?
문제 해결 과정을 확인
사고의 흐름을 파악
: 문제 발견 -> 분석 -> 선택지 비교 -> 해결

동시성 문제로 데이터가 꼬임, 
N+1 문제로 조회 성능이 떨어짐, 
트랜잭션 범위가 너무 커서 장애 포인트가 생김, 
외부 API 연동 불안정으로 재시도 로직이 필요함 등

문제 원인을 어떻게 찾았고, 로그나 모니터링으로 무엇을 확인했고, 해결 이후 어떤 개선이 있었는지
이것이 AI가 대체하지 못하는 **경험 기반 사고**

###### 3. 지금 다시 설계한다면 어떻게 바꾸고 싶은가요?
회고할 줄 아는 개발자인지를 확인

예시:
"시간이 부족하여 캐싱 전략을 단순하게 가져갔는데,
다시 설계한다면 Redis 클러스터를 도입하고 캐시 무효화 정책도 세분화하겠다"
"당시에는 프로젝트 일정상 2주 안에 MVP를 내야 해서 모놀리식으로 진행, 
하지만 다시 설계한다면 인증과 알림처럼 변경 가능성이 큰 부분은 분리해서 설계할 것이다"

한계를 인정하면서도 개선 방향을 구체적으로 제시
약점을 정확히 아는 사람 = 진짜 실력자
