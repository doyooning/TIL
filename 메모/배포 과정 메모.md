# 환경 변수
각종 환경 변수를 등록하고 프론트에서 호출함
.env
.env.local
.env.development
.env.development.local 등으로 유지

Vite는 `import.meta.env`에 자동으로 위 환경 변수들을 자동으로 합쳐서 넣음

사용 방법
```js
const apiBase = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080'  
const oauthBase = import.meta.env.VITE_OAUTH_BASE_URL || window.location.origin
```


# 환경 변수 적용 방법

### 1) EC2에서 `systemd` 서비스로 환경변수 주입

**(1) EC2에 env 파일 만들기**

예: `/opt/deskit/deskit.env`
```bash
sudo mkdir -p /opt/deskit 
sudo nano /opt/deskit/deskit.env
```

내용:
```bash
OPENAI_API_KEY=xxxx 
REDIS_AUTH_TOKEN=xxxx 
AWS_REGION=ap-northeast-2
```

권한(중요):
```bash
sudo chown root:root /opt/deskit/deskit.env sudo chmod 600 /opt/deskit/deskit.env
```

**(2) systemd 서비스에 연결**

`/etc/systemd/system/deskit.service`
```bash
[Unit] 
Description=deskit app 
After=network.target  

[Service] 
User=ec2-user 
EnvironmentFile=/opt/deskit/deskit.env 
ExecStart=/usr/bin/java -jar /opt/deskit/deskit.jar 
Restart=always 
SuccessExitStatus=143  

[Install] 
WantedBy=multi-user.target
```

적용:
```bash
sudo systemctl daemon-reload 
sudo systemctl restart deskit 
sudo systemctl status deskit
```

✅ 이 방식이면 `application-prod.yml`에서
```bash
password: ${REDIS_AUTH_TOKEN} 
api-key: ${OPENAI_API_KEY}
```

이렇게 쓰는 게 적용됨

### 2) Docker로 띄운다면: `--env-file` 사용

`docker run --env-file .env.production -p 8080:8080 deskit:latest`

또는 docker-compose:
```yaml
services:
  app:
    env_file:
      - .env.production
```

### 3) GitHub Actions 배포라면: Secrets → SSH로 export/파일 생성

**가장 안전: GitHub Secrets에 넣고 EC2에 env 파일 생성**

예(개념):

- `OPENAI_API_KEY`, `REDIS_AUTH_TOKEN`을 GitHub Secrets에 저장
- 배포 단계에서 EC2에 접속해서:
```bash
cat > /opt/deskit/deskit.env << 'EOF'
OPENAI_API_KEY=${OPENAI_API_KEY}
REDIS_AUTH_TOKEN=${REDIS_AUTH_TOKEN}
EOF
chmod 600 /opt/deskit/deskit.env
systemctl restart deskit
```

> 여기서 `${OPENAI_API_KEY}` 같은 값은 **Actions가 주입**해줌

✅ `.env.production`을 repo에 올리지 않아도 되고, 키 유출 위험이 낮음


# 프론트 배포하기
### EC2에 Nginx로 정적 배포
로컬에서 빌드 → `dist/`를 EC2로 복사 → Nginx가 `dist` 서빙

### 1) 로컬에서 빌드

```bash
cd front
npm ci
npm run build
```
빌드 결과물이 보통 `front/dist/`에 생김

### 2) EC2로 업로드

intellij에서 EC2 서버로 ssh 연결
(ubuntu@도메인주소)

front/dist에서 다이렉트로 var/www로 못 옮김(권한 문제) 

대안:
홈 디렉터리에 먼저 업로드 → sudo로 이동
프로젝트에서 Remote Host의 /home/ubuntu/dist에 옮겨줌

그 다음 EC2 sudo로 이동
```bash
sudo mkdir -p /var/www/deskit
sudo cp -r ~/deskit-dist/* /var/www/deskit/
sudo chown -R www-data:www-data /var/www/deskit
```


### 3) Nginx 설정

default 파일 수정
```bash
sudo nano /etc/nginx/sites-available/default
```

해당하는 부분 수정
```nginx
server {
  listen 80;
  server_name your-domain.com;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl;
  server_name your-domain.com;

  root /var/www/deskit;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  # 백엔드 API 프록시(선택: same-origin으로 CORS 줄이기)
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```
설정 꼼꼼히 위와 같이 해당 부분 수정

변경 사항 적용
```bash
sudo nginx -t
sudo systemctl reload nginx
```


### 트러블슈팅

**sudo 권한 필요할 때**
비번 설정 먼저 필요
```bash
sudo passwd ubuntu
```

완료되면 `sudo systemctl daemon-reload`


**nginx 설정 파일이 어디를 보는지 확인**
```bash
nginx -V 2>&1 | grep -oE "conf-path=[^ ]+" || true
nginx -T 2>/dev/null | head -n 40
```

`/etc/nginx/conf.d/default.conf` 가 있는 경우
그걸 수정하면 됨

**설정 파일 제대로 적용되었는지 확인**
```bash
sudo nginx -T 2>/dev/null | grep -n "server_name" | head -n 50
sudo nginx -T 2>/dev/null | grep -n "root " | head -n 50
```
server_name 부분이랑 root 부분 확인


**80/443 포트 누가 듣고 있는지 확인**
EC2에서
```bash
sudo ss -lntp | egrep ':(80|443)\b' || true
docker ps --format "table {{.Names}}\t{{.Ports}}\t{{.Status}}" | egrep 'nginx|openvidu|:80->|:443->' || true
```

내 nginx인지 확인
```bash
curl -I http://localhost 2>/dev/null | egrep -i 'server:|date:|location:'
curl -I https://localhost 2>/dev/null | egrep -i 'server:|date:|location:'
```
