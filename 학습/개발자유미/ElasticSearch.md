# 동작 원리
**모식도**
수많은 문서 중 검색어에 대해 특정 문서를 빠르고 정확하게 찾기 위해선 아래 과정이 필요함

- 문서를 기반으로 인덱스를 만드는 부분
- 만들어진 인덱스를 기반으로 검색을 하는 부분
![[Pasted image 20260202135527.png]]

**인덱스(색인)**
문서를 빠르게 찾을 수 있도록 만든 테이블
![[Pasted image 20260202135604.png]]

**인덱스를 만드는 과정**
가장 중요한 포인트
문서를 전처리 → 형태소 분석 → 후처리 과정을 통해 의미 있는 형태소만 인덱스로 만들어 검색이 잘 될 수 있도록 해야 함
![[Pasted image 20260202135729.png]]

**주요 포인트**
동일한 문서에 대해서도 
전처리 → 형태소 분석 → 후처리 과정을 통해 인덱스를 만든 결과에 따라 전혀 다른 검색 결과를 가질 수 있음

- 후처리 단계에서 영어 대문자를 모두 소문자로 바꿈 : 대소문자 검색 결과가 같음
- 형태소 분석 단계에서 운동화가 "운 + 동화" 로 분리 됨 : 동화라고 검색했는데, 운동화 문서가 검색 됨

이 부분이 여타 DB와도 비교되는 부분(ElasticSearch가 검색 엔진으로 불리는 이유)

MongoDB, MySQL과 같은 데이터베이스도 FTS(Full Text Search)를 지원하지만, 
위 과정을 강력하게 커스텀 할 수 없기 때문에 검색에는 꼭 Elasticsearch가 필요함
