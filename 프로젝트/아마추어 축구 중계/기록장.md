# *기획 단계*

# 큰 그림
### 1. 이 서비스에서 “영상”은 필수인가요, 아니면 보조인가요?
지금 배경상으로는 라이브 영상이 이미 켜지고 있고, 거기에 경기 정보가 부족해서 시작한 프로젝트입니다.
그래서 확인할 부분은:
- 이 프로젝트의 핵심이 **중계 영상 자체 제공**인지
- 아니면 **영상 위/옆에서 경기 정보를 보완하는 것**인지
이건 중요합니다.  
왜냐하면 MVP가 많이 달라집니다.
- 영상 자체 제공이 핵심이면 스트리밍 안정성이 매우 중요
- 정보 보완이 핵심이면 스코어/시간/이벤트 UX가 더 중요
지금 설명만 보면 저는 후자에 더 가깝다고 느껴집니다.

> 영상 + 정보 + 채팅 이렇게 구성, 영상을 주로 폰 카메라로 찍어서 막 화질이 좋진 않아서 정보 제공이 조금 더 중요하게 느껴짐

### 2. 경기 정보를 입력하는 사람은 누구인가요?
이건 사용자 역할 구분 전에 꼭 생각해봐야 합니다.
예를 들면:
- 촬영하는 사람이 직접 기록도 같이 하는지
- 별도의 기록 담당 1명이 있는지
- 운영진만 입력 가능한지
이게 확정돼야 기능 난이도가 정해집니다.  
혼자 촬영하면서 기록까지 해야 하면 입력 UX를 아주 단순하게 해야 합니다.

> 촬영 1명, 별도의 기록 담당 1명(운영진)

### 3. 시청자는 어디서 이 서비스를 보게 되나요?
이것도 초기에 중요합니다.
예:
- 별도 웹페이지
- 모바일 웹
- 유튜브 라이브와 같이 켜는 보조 페이지
- 앱처럼 보이는 웹뷰/PWA
지금 “앱 환경처럼” 생각하고 계시긴 하지만, MVP는 아마 **모바일 웹**이 가장 현실적일 가능성이 큽니다.

> 모바일 웹으로 생각하고 있는데 유튜브 라이브와 같이 켜는 보조 페이지 나쁘지 않은데...?
> 1순위 모바일 웹 - 2순위 그냥 보조 페이지(영상 없이, 대신 네이버 스포츠처럼 실시간 상황을 문자로 알려줌)

### 4. 시청자가 가장 먼저 알아야 하는 정보는 정확히 무엇인가요?
지금까지 나온 건:
- 몇 대 몇
- 몇 분 남았는지
여기에 하나 더 필요한지 생각해보셔야 합니다.
예:
- 전반/후반 여부
- 누가 골 넣었는지
- 경기 시작/종료 여부
이 질문은 기능 정의 우선순위를 정하는 데 중요합니다.

> 다 필요함, 퇴장 선수 여부도 반드시 필요하고 추가적으로는 우리 팀 라인업 제공

### 5. MVP에서 “싸투 경기만” 다룬다면 상대팀 정보는 어느 정도까지 필요한가요?
단일팀 시스템이어도 경기는 상대팀이 있어야 하니,
- 상대팀 이름만 있으면 되는지
- 상대팀 선수 정보도 필요한지
- 이벤트 기록에서 상대팀 득점자까지 입력할 건지
이건 나중 DB 이전에 기획상 먼저 정해두면 좋습니다.

> 일단은 상대팀 이름도 모르는 경우가 많아서 정보 필요 없을 듯
> 상대편 정보는 그냥 스코어랑 레드카드 개수 정도만 제공


# 사용자 구분
## 🎯 1) 운영자 (Admin)
역할:
- 경기 생성
- 응원방 열기 / 닫기
- 경기 상태 변경 (전반/후반/종료)
- 라인업 설정
👉 쉽게 말하면 “경기 관리 책임자”

## 🎯 2) 기록자 (Recorder)
역할:
- 이벤트 입력
    - 골
    - 카드
    - 파울
    - 교체
👉 “버튼 누르는 사람”

## 🎯 3) 시청자 (Viewer)
역할:
- 영상 시청 (유튜브)
- 경기 정보 확인
- (선택) 채팅 참여
