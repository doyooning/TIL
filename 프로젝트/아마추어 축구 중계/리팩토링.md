#프로젝트

---
1. **매치 운영 페이지 분해 (최우선)**
    - 대상: app/manager/match/[id]/page.tsx
    - 분리 단위:
        - useMatchMeta (match, teams, lineups, players 로드)
        - useMatchTimeline (events 로드/정렬/undo)
        - useMatchClock (전반/후반/연장 stopwatch + period/minute 계산)
        - useMatchActions (start/end/toggle/saveEvent/savePenalty)
        - UI 컴포넌트 분리: ScoreBoard, TimePanel, PenaltyPanel, EventForm, EventTimeline
    - 효과: 컴파일/디버깅 속도 개선, 기능 추가 시 충돌 감소

2. **Supabase 쿼리 레이어 분리**
    - 현재 페이지 컴포넌트 안에 .from(...) 호출이 많음
    - lib/repositories 또는 lib/services로 이동:
        - matchRepo.ts, eventRepo.ts, lineupRepo.ts
    - 효과: 컬럼명 변경 대응 속도 상승, 중복 쿼리 제거

3. **도메인 로직 유틸화**
    - 득점/자책골 스코어 반영, 선수 상태 변경(sub_in/sub_out/sent_off), 이벤트 설명 생성 로직을 pure function으로 분리
    - 예: lib/match/event-rules.ts, lib/match/clock.ts
    - 효과: 테스트 가능한 구조 확보, 회귀 버그 감소

4. **상태관리 단순화 (useReducer)**
    - useState가 많은 화면은 이벤트 처리 누락/경합이 생기기 쉬움
    - 매치 운영 페이지는 reducer로 전환 권장 (ui state, clock state, event form state)
    - 효과: 복잡한 상태 전이 안정화

5. **페이지 공통 UI/로직 재사용**
    - 매치 카드/스코어/타임라인 포맷터를 운영자/시청자 페이지에서 공통화
    - 대상 참고: components/match/match-list.tsx, components/match/match-info-tab.tsx
    - 효과: 표시 불일치 방지
