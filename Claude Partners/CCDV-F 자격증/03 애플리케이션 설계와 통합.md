# D2-2. 애플리케이션 설계와 통합 (D2 = 33.1%)

> 세부: 요구사항 이해 3.4% / 시스템 생명주기 2.8% / SW 엔지니어링 기초 7.4% / Claude 애플리케이션 설계 8.6% / 구성 관리 4.1%

## 1. 개발 여정 (시스템 생명주기)

```
시작하기 → 빌드 → 평가 및 출시 → 운영
```

| 단계 | 할 일 |
| --- | --- |
| **시작** | 모델 선택, API 키 발급, SDK 설치, Playground에서 실험 |
| **빌드** | Messages API, 사고, 비전, 도구 사용, 웹 검색, 코드 실행, 구조화된 출력, 프롬프트 캐싱, 스트리밍 |
| **평가·출시** | 프롬프트 모범 사례, eval 실행, 배치 테스트, 안전·가드레일, 속도 제한·오류 처리, 비용 최적화 |
| **운영** | 워크스페이스·관리, API 키 관리, 사용량 모니터링, 모델 마이그레이션 |

### 빌드 방식 선택
| 방식 | 특징 |
| --- | --- |
| **Messages** | 모델에 직접 접근. 매 턴을 직접 구성하고 대화 상태를 관리하며 **자체 도구 루프**를 작성 |
| **Managed Agents** | 완전 관리형 에이전트 인프라. 영구 이벤트 기록을 갖춘 **상태 유지 세션**에서 자율 에이전트 배포·관리 |
| **Agent SDK** | Claude Code의 에이전트 루프를 내 애플리케이션에 임베드 |

## 2. 멀티모달 입력

### 비전(이미지)

세 가지 소스 타입:
1. `{"type": "base64", "media_type": "...", "data": "..."}`
2. `{"type": "url", "url": "https://..."}`
3. `{"type": "file", "file_id": "file_..."}` (Files API)

> Bedrock·Google Cloud에서는 **base64만** 지원.

| 항목 | 값 |
| --- | --- |
| 지원 형식 | JPEG, PNG, GIF, WebP (애니메이션 미지원, 첫 프레임만) |
| 이미지당 최대 크기 | Claude API 10 MB / Bedrock·Google Cloud 5 MB |
| 이미지당 최대 픽셀 | 8000 × 8000 px |
| 요청당 최대 개수 | 200k 컨텍스트 모델 100개, 그 외 **600개** (claude.ai는 턴당 20개) |
| 이미지 21개 이상일 때 | 요청 내 **모든** 이미지에 더 엄격한 개별 크기 제한 적용 → 각 변 2000 px 이하로 |

**토큰 계산**: Claude는 이미지를 **28×28 픽셀 패치**로 본다.
```
비주얼 토큰 = ⌈width / 28⌉ × ⌈height / 28⌉
```

| 해상도 등급 | 모델 | 최대 긴 변 | 최대 비주얼 토큰 |
| --- | --- | --- | --- |
| 고해상도 | Claude 4.7 이후 | 2576 px | 4784 |
| 표준 | 그 외 | 1568 px | 1568 |

제한을 넘는 이미지는 **종횡비를 유지한 채 축소**되므로 토큰 비용에 상한이 생긴다. `tool_result` 이미지는 축소 대신 **검증 오류로 거부**되므로 애플리케이션에서 미리 리사이즈해야 한다.

**팁**: 이미지를 텍스트보다 **앞에** 두면 성능이 좋다. 여러 이미지를 보낼 때는 각각 앞에 `Image 1:` 같은 레이블을 붙인다.

**제한**: 인물 식별 거부, 200px 미만 소형 이미지·회전 이미지에서 환각 가능, 좌표·개수 세기는 근사치, AI 생성 이미지 판별 불가, 복잡한 진단 스캔 해석 불가.

### Files API

```
POST   /v1/files              업로드
GET    /v1/files              목록(page/next_page 커서, ids[]로 최대 100개 조회)
GET    /v1/files/{id}         메타데이터
GET    /v1/files/{id}/content 다운로드
DELETE /v1/files/{id}         삭제
```

| 파일 유형 | MIME | 콘텐츠 블록 |
| --- | --- | --- |
| PDF | `application/pdf` | `document` |
| 일반 텍스트 | `text/plain` | `document` |
| 이미지 | `image/jpeg|png|gif|webp` | `image` |
| 데이터셋 등 | 다양 | `container_upload` (코드 실행 도구용) |

| 제한 | 값 |
| --- | --- |
| 파일당 최대 크기 | **500 MB** |
| 조직 총 저장 용량 | **1 TB** |
| 파일 API 속도 제한 | 약 500 RPM (업로드·목록·다운로드·삭제 공유) |
| 만료 | `expires_in_seconds` 3,600~7,776,000초(1시간~90일), 업로드 시 1회 설정·변경 불가 |
| 비용 | **파일 작업 자체는 무료**. Messages에서 쓰인 콘텐츠만 입력 토큰으로 과금 |

**보안 경고(시험 포인트)**: 업로드된 파일은 **워크스페이스 전체에서 접근 가능**하다. 세션·사용자 단위로 격리되지 않는다.
- 워크스페이스에 접근 가능한 모든 API 키가 모든 파일을 읽을 수 있다
- **최종 사용자로부터 `file_id`를 받지 말 것** — 한 사용자가 다른 사용자의 파일을 읽게 된다
- 멀티테넌트 앱은 **테넌트당 워크스페이스**를 분리한다(조직당 최대 100개)
- `downloadable: true`인 파일만 다운로드 가능 = **스킬/코드 실행 도구가 생성한 파일만**. 내가 업로드한 파일 다운로드는 400

### .docx / .xlsx
`document` 블록이 지원하지 않는다. 일반 텍스트로 변환해 인라인 포함하거나, 이미지가 있는 .docx는 **PDF로 변환**해 PDF 지원(내장 이미지 파싱 + 인용)을 활용한다.

## 3. 배치 처리 (Message Batches API)

즉시 응답이 필요 없는 대량 작업을 비동기로 처리하고 **입력·출력 50% 할인**을 받는다.

| 항목 | 값 |
| --- | --- |
| 배치당 최대 | **100,000 요청** 또는 **256 MB** (먼저 도달하는 쪽) |
| 처리 시간 | 대부분 1시간 이내, **24시간 내 미완료 시 만료** |
| 결과 보존 | 생성 후 **29일** (이후에도 배치 조회는 되지만 결과 다운로드 불가) |
| 범위 | **워크스페이스 단위** 격리 |
| `processing_status` | `in_progress` → `ended` (취소 시 `canceling`) |

### 결과 타입 (`request_counts`로 집계)
| 타입 | 의미 | 과금 |
| --- | --- | --- |
| `succeeded` | 성공 | O |
| `errored` | 오류(잘못된 요청, 내부 오류) | **X** |
| `canceled` | 모델 전송 전 사용자 취소 | **X** |
| `expired` | 24시간 만료 도달 | **X** |

### 배치에서 지원되는 것 / 안 되는 것
- **지원**: 비전, 모든 서버 도구(웹 검색·웹 가져오기·코드 실행·MCP 커넥터·advisor·tool search), 시스템 메시지, 멀티턴, extended thinking, 대부분의 베타
- **미지원(검증 오류)**: `stream: true`, `speed`(Fast mode), `max_tokens: 0`

### 모범 사례
- 결과는 **순서가 보장되지 않는다** → 의미 있는 `custom_id`로 매칭 (배치 내 고유해야 함)
- 배치 전에 Messages API로 **단일 요청 dry run**하여 검증 오류를 미리 잡는다
- 아주 큰 데이터셋은 여러 배치로 분할
- 배치는 5분 이상 걸리므로 공유 컨텍스트가 있다면 **1시간 캐시**와 함께 쓴다
- 배치 루프는 동기 요청보다 **턴당 반복을 더 많이** 돌고 `pause_turn`을 반환한다
- 한 요청의 실패가 다른 요청에 영향을 주지 않는다

## 4. 구조화된 출력

응답이 스키마를 따르도록 **제약된 디코딩**으로 강제한다.

| 기능 | 파라미터 | 대상 |
| --- | --- | --- |
| JSON 출력 | `output_config.format` (`type: "json_schema"`) | 최종 텍스트 응답 |
| 엄격한 도구 사용 | 도구 정의의 `strict: true` | 도구 이름·입력 |

> 베타에서 `output_format` → **`output_config.format`** 으로 이동했고 베타 헤더는 불필요.

### JSON Schema 제한
- **지원**: 기본 타입 전부, `enum`(스칼라만), `const`, `anyOf`/`allOf`(`$ref` 있는 `allOf`는 불가), `$ref`/`$defs`(외부 `$ref` 불가), `default`, `required`, 문자열 format(date-time, email, uri, uuid 등), 배열 `minItems`는 **0 또는 1만**
- **필수**: 객체는 `additionalProperties: false`
- **미지원**: 재귀 스키마, enum 내 복합 타입, 외부 `$ref`, 숫자 제약(`minimum` 등), 문자열 길이 제약, 정규식의 역참조·전후방탐색·단어 경계
- **속성 순서**: 스키마 순서를 유지하되 **필수 속성이 먼저, 선택 속성이 뒤**

### 복잡도 한도 (요청 내 모든 strict 스키마 합산)
| 한도 | 값 |
| --- | --- |
| strict 도구 | 20개 |
| 선택적 파라미터 | 24개 |
| 유니온(`anyOf`/타입 배열) 파라미터 | 16개 |

초과 시 `Schema is too complex for compilation.` 400. 완화 순서: ① 중요한 도구만 strict ② 선택 파라미터를 `required`로 ③ 중첩 평탄화 ④ 여러 요청/서브에이전트로 분할

### 성능·호환성
- 스키마 첫 사용 시 **문법 컴파일 지연**, 이후 **24시간 캐시**. 스키마 구조나 도구 집합이 바뀌면 무효화(`name`/`description`만 바꾸는 건 무효화 안 됨)
- 추가 시스템 프롬프트가 자동 주입되어 입력 토큰이 약간 늘고, `output_config.format` 변경은 **프롬프트 캐시를 무효화**한다
- 함께 사용 가능: 배치 처리, 토큰 카운팅, 스트리밍, JSON 출력 + strict 도구 동시 사용
- **비호환**: 인용(citations), 메시지 프리필링
- 문법은 **Claude의 직접 출력에만** 적용되고 도구 호출·도구 결과·thinking 태그에는 적용되지 않는다
- HIPAA 적격이지만 **PHI를 스키마 정의에 넣으면 안 된다**(스키마는 별도로 24시간 캐시됨)

## 5. SDK와 클라이언트

- 공식 SDK: **Python, TypeScript, C#, Go, Java, PHP, Ruby** + `ant` CLI
- 기능: 스트리밍 누적, 자동 재시도(기본 2회, 지수 백오프, `retry-after` 준수), 타입 지정 예외, 자동 페이지네이션 헬퍼, 스키마 변환 헬퍼
- **Tool Runner**(`client.beta.messages.tool_runner`)를 쓰면 도구 루프를 직접 작성하지 않아도 된다
- Python SDK의 `ClaudeSDKClient`는 세션 ID를 자동 관리한다(Agent SDK)

### 클라우드 플랫폼
| 플랫폼 | 특징 |
| --- | --- |
| **Claude API**(퍼스트파티) | 기본 global 라우팅 |
| **Claude Platform on AWS** | AWS Marketplace 청구(CCU), Anthropic 운영 |
| **Amazon Bedrock** | 글로벌/리전 엔드포인트. 리전은 10% 프리미엄 |

## 6. 구성 관리 (4.1%)

### 워크스페이스
- 조직 내 **리소스 격리 경계**. API 키·파일·배치가 워크스페이스 범위로 묶인다
- 조직당 **최대 100개**
- 워크스페이스별 **지출 한도·속도 제한**을 낮게 설정할 수 있다(기본 워크스페이스는 불가). 설정하지 않으면 조직 제한과 동일
- 응답의 `anthropic-workspace-id` 헤더로 어느 워크스페이스에 집계됐는지 확인

### API 키 관리
- `ANTHROPIC_API_KEY` 환경변수로 주입. **코드·저장소에 하드코딩 금지**
- 키는 만료될 수 있다(401 `authentication_error`)
- 분리가 필요한 자원(특히 파일)은 **전용 워크스페이스 + 해당 워크스페이스 범위 키**로 접근

### 모니터링
- Console **Usage** 페이지: 토큰·요청 차트 + 속도 제한 차트(캐시 비율 포함)
- **Usage & Cost API**로 프로그래밍 방식 조회
- **Rate Limits API**로 현재 조직·워크스페이스 제한 조회
- **Compliance API / Activity Feed**로 Files API 작업 감사(`platform_file_uploaded`, `platform_file_content_downloaded`, `platform_file_deleted`). 끄져 있는 동안의 작업은 **소급 복구 불가**

### 모델 마이그레이션
- 모델 ID는 고정 스냅샷이므로 새 모델로 올릴 때 **토큰 수를 다시 측정**한다(4.7 이후 토크나이저 변경으로 약 30% 증가)
- thinking 파라미터 호환성 확인(`enabled` ↔ `adaptive`)
- 프리필을 쓰고 있었다면 구조화된 출력으로 전환
- 마이그레이션 가이드와 모델별 프롬프팅 페이지를 먼저 읽는다

## 7. 요구사항 이해 (3.4%)

Claude 애플리케이션을 설계할 때 먼저 정해야 할 것:
1. **성공 기준**(정량 지표 + 허용 오차) → [[09 평가 테스트 디버깅]]
2. **지연 시간·비용 예산** → 모델 티어 선택
3. **데이터 민감도** → 워크스페이스 격리, ZDR, 데이터 레지던시(`inference_geo`)
4. **실시간성** → 동기 / 스트리밍 / 배치
5. **결정론 요구 수준** → 구조화된 출력, strict 도구
6. **외부 시스템 연동 범위** → 클라이언트 도구 / 서버 도구 / MCP
