# 프로덕션 엔지니어링 · 배포 · 재사용

> 공식 prep 모듈 **4(Production Engineering, Evals & Security)** 와 **5(Accelerators & IP Contribution)** 의 학습 목표 중 기존 노트 01~10에 빠져 있던 부분.

## 1. 테스트 계층과 추적

공식 학습 목표: *"단위, 기능, 통합, 엔드투엔드 수준에서 회귀를 감지하는 테스트·추적 계층 구축"*

| 계층 | 대상 | LLM 호출 | 예 |
| --- | --- | --- | --- |
| **Unit** | 순수 함수 | ❌ (모킹) | 청킹 함수, 프롬프트 템플릿 렌더링, 도구 입력 검증, `tool_result` 조립 |
| **Functional** | 하나의 LLM 상호작용 | ✅ | 이 프롬프트가 스키마에 맞는 JSON을 내는가, 이 도구를 선택하는가 |
| **Integration** | 여러 컴포넌트 | ✅ | 도구 루프가 `tool_use` → 실행 → `tool_result` → 최종 답변까지 도는가, MCP 서버 연결 |
| **End-to-end** | 사용자 여정 전체 | ✅ | 실제 질의 → 검색 → 에이전트 → 최종 산출물 |

### LLM이 끼면 테스트가 달라지는 점
- **비결정성**: 샘플링 때문에 같은 입력도 출력이 달라진다 → 정확 일치 단언은 대부분 깨진다
  - 완화: `temperature` 낮추기, **구조화된 출력으로 형태를 고정**, 내용은 **채점기(grader)** 로 판정
- **회귀 감지**: 프롬프트·모델·도구 스키마 중 하나만 바뀌어도 회귀가 난다 → **eval 스위트를 CI에 건다**
- **비용**: LLM이 끼는 계층은 느리고 비싸다 → **Unit을 두텁게, E2E는 얇게**, 대량 eval은 **Batch API**로

### 추적(tracing)
| 남길 것 | 이유 |
| --- | --- |
| `request-id` | 지원 문의·재현 |
| 모델 ID, 프롬프트 버전, 도구 스키마 버전 | 회귀 원인 특정 |
| `usage`(입력/출력/캐시 생성/캐시 읽기) | 비용·캐시 적중률 |
| `stop_reason`, `stop_details` | 잘림·거부 탐지 |
| 턴 수, 도구 호출 이름·결과 크기 | 루프 폭주 탐지 |
| 지연 시간(TTFT, 전체) | SLO |

Agent SDK는 **OpenTelemetry 관측성**을 제공한다. Claude Code는 `--include-hook-events`, `--output-format stream-json`으로 이벤트를 파이프라인에 넘길 수 있다.

## 2. 재시도 가능 오류 vs 종료(terminal) 오류

공식 학습 목표: *"재시도 가능 오류와 종료 오류를 구분해 프로덕션 장애에 견디는 애플리케이션"*

| 분류 | 코드 / 신호 | 대응 |
| --- | --- | --- |
| **재시도 가능(transient)** | 429(`retry-after` 있음), 500 `api_error`, 504 `timeout_error`, 529 `overloaded_error`, 연결 오류 | **지수 백오프 + 지터**, `retry-after` 준수, 최대 시도 횟수 제한 |
| **재시도 가능하지만 조건부** | 409 `conflict_error` | 충돌 해소 후 재시도 |
| **종료(terminal) — 재시도 무의미** | 400 `invalid_request_error`, 401, 402, 403, 404, 413 | 요청/설정을 고치기 전엔 계속 실패. **재시도 금지** |
| **종료처럼 보이는 429** | `retry-after` **없음** + `error_code: enforced_spend_limit_reached` | 티어 지출 상한. 액세스 재개까지 계속 실패 → **알림을 띄우고 중단** |
| **오류가 아닌 것** | `stop_reason`(HTTP 200) | 별도 분기. `max_tokens`는 "잘림", `refusal`은 "거부" |

### 구현 지침
- 공식 SDK는 **기본 2회 지수 백오프 재시도**를 하고 `retry-after`를 따른다. 애플리케이션 레벨 재시도를 또 얹으면 **중복 증폭**되므로 한쪽으로 통일한다
- **타입 지정 예외로 분기**한다(문자열 매칭 금지)
- **멱등성**: 도구가 부수효과를 내는 경우, 재시도가 중복 실행을 일으키지 않도록 멱등 키를 둔다
- **서킷 브레이커**: 연속 5xx/529가 임계치를 넘으면 잠시 차단하고 폴백
- **폴백 체인**: `refusal`이나 모델 불가 시 다른 모델로 폴백
- **10분 초과 가능성**이 있으면 처음부터 스트리밍 또는 Batch API

## 3. 비용·지연 시간·신뢰성 예산

공식 학습 목표: *"여러 에이전트에 걸친 작업에서 비용·지연 시간·신뢰성 예산 안에서 운영"*

| 예산 | 통제 수단 |
| --- | --- |
| **비용** | `max_budget_usd`(서브에이전트 포함), 모델 티어 선택, 프롬프트 캐싱, Batch 50% 할인, `effort` 낮추기, 워크스페이스 지출 한도 |
| **지연 시간** | 스트리밍(TTFT 개선), 캐시 사전 워밍, 저지연 모델(Haiku), Fast mode, 병렬 도구 호출, 컨텍스트 축소 |
| **턴 수** | `max_turns` |
| **처리량** | 프롬프트 캐싱(캐시 읽기는 ITPM에서 제외), 티어 상향 요청, 워크스페이스별 제한 분배 |
| **신뢰성** | 재시도 정책, 폴백 모델, 서킷 브레이커, eval 게이트 |

### 멀티 에이전트에서 특히 주의
- 예산은 **트리 전체 합산**이다. `max_budget_usd` 초과 시 서브에이전트 생성이 `Budget limit reached`로 실패하고 백그라운드 서브에이전트도 중단된다
- `usage`는 메인 루프만 센다. 전체 트리 회계는 **`modelUsage` / `model_usage`** 를 본다
- 동시 서브에이전트 기본 20개, 중첩 깊이 기본 3

## 4. 에이전트 메모리와 스코프

공식 학습 목표: *"세션 간 에이전트 메모리를 영속 저장 패턴과 올바른 메모리 스코프 선택으로 관리"*

| 메커니즘 | 범위 | 특성 |
| --- | --- | --- |
| **대화 히스토리** | 세션 내 | 압축되면 요약으로 대체된다 |
| **메모리 도구**(API) | 앱이 관리하는 파일 | Anthropic 스키마 클라이언트 도구. **컨텍스트 편집과 조합**하면 지워지기 전에 요점을 파일로 옮길 수 있다 |
| **CLAUDE.md / rules** | 프로젝트·사용자·조직 | 매 세션 로드. **압축 후 디스크에서 재주입** |
| **auto memory** | 저장소 단위, 머신 로컬 | Claude가 스스로 기록. `MEMORY.md` 첫 200줄/25KB만 로드 |
| **서브에이전트 `memory`** | `user` / `project` / `local` | 서브에이전트 전용 메모리 디렉터리 |
| **세션 저장소** | 외부 백엔드 | Agent SDK `session_store` 어댑터 — 스테이트리스 호스트에서 resume 가능 |
| **외부 DB / 벡터 스토어** | 애플리케이션 | 장기 사실·사용자 프로필 |

### 스코프 선택 기준
| 질문 | 답 |
| --- | --- |
| 팀 전체가 공유해야 하나? | 프로젝트 CLAUDE.md (커밋) |
| 나만 쓰나? | 사용자 스코프 / local |
| 세션이 끝나도 남아야 하나? | 메모리 도구 · auto memory · 외부 저장소 |
| 여러 머신·컨테이너에서 이어야 하나? | **외부 세션 저장소** (auto memory는 머신 로컬) |
| 압축을 넘겨 살아남아야 하나? | 디스크 기반(CLAUDE.md, 메모리 파일) — 대화 중 지시는 사라진다 |

## 5. 배포 플랫폼 선택

공식 학습 목표: *"퍼스트파티 API / Amazon Bedrock / Google Vertex AI / 서드파티 플랫폼 중 어디서 실행할지 선택하고, 지연 시간·컴플라이언스·비용으로 비교"*

| 플랫폼 | 청구 | 모델 ID | 특징 |
| --- | --- | --- | --- |
| **Claude API** (퍼스트파티) | Anthropic 직접 | `claude-opus-5-5` | 기본 global 라우팅, 최신 기능이 가장 먼저 |
| **Claude Platform on AWS** | AWS Marketplace(**CCU**) | Claude API ID 사용 | Anthropic 운영, Anthropic 모델 수명주기, 후불만 가능 |
| **Amazon Bedrock** | AWS 직접 | `anthropic.claude-opus-5-5` | 글로벌/리전 엔드포인트, **리전은 10% 프리미엄**, AWS가 수명주기 결정 |
| **Google Cloud (Vertex)** | GCP 직접 | `claude-opus-5-5` | 글로벌/멀티리전/리전, GCP가 수명주기 결정 |
| **Microsoft Foundry** | Azure Marketplace(CCU) | 배포 이름 | US Data Zone 배포 가능, Claude API 수명주기 따름 |

### 비교 축

| 축 | 고려사항 |
| --- | --- |
| **지연 시간** | 글로벌 엔드포인트(동적 라우팅)가 일반적으로 빠름. 리전 고정은 지연 ↑ |
| **컴플라이언스·데이터 레지던시** | 리전 엔드포인트가 **데이터 라우팅을 보장**. 퍼스트파티는 `inference_geo: "us"`(1.1x) |
| **비용** | 리전/멀티리전 엔드포인트 10% 프리미엄, `inference_geo: "us"` 1.1x, CCU 환산은 동일 요율 |
| **조달** | 기존 AWS/Azure 계약과 마켓플레이스 청구를 쓸 수 있는가 |
| **기능 가용성** | 일부 기능은 파트너 플랫폼에서 미지원(예: **Files API는 Bedrock·Google Cloud에서 사용 불가**, 비전은 base64만) |
| **모델 수명주기** | Bedrock·Google Cloud는 **자체 종료 일정**을 정한다 |

### 기능 가용성 함정 (시험에 좋은 소재)
| 기능 | 제약 |
| --- | --- |
| Files API | Claude API GA / AWS·Foundry 베타 / **Bedrock·Google Cloud 미지원** |
| 비전 이미지 소스 | Bedrock·Google Cloud는 **base64만** (url·file_id 불가) |
| Fast mode | **Claude API 전용** |
| 구조화된 출력 | Bedrock은 일부 모델만 |
| `inference_geo` | Claude 4.6 이후 모델만. 이전 모델에 보내면 400 |
| 이미지 크기 | Bedrock·Google Cloud는 **5 MB**(Claude API 10 MB) |

## 6. Accelerator 패키징과 버전 관리

공식 학습 목표: *"동작하는 솔루션을 재사용 가능한 accelerator로 패키징 — 파라미터화된 에이전트 템플릿, 구성 가능한 MCP 서버, 이식 가능한 eval 스위트"*

| 자산 유형 | 패키징 형태 | 이식성 포인트 |
| --- | --- | --- |
| **에이전트 템플릿** | 서브에이전트 정의(`.claude/agents/*.md`) + `--agents` JSON | 프론트매터로 모델·도구·권한을 파라미터화 |
| **워크플로** | **Skill**(`SKILL.md`) | **한 번 작성하면 Claude Code / Messages API / Agent SDK에서 동일하게 동작** |
| **도구 묶음** | **MCP 서버** | transport와 **구성 스코프**(local/project/user)로 누가 로드할지 제어. 환경변수 확장으로 환경별 구성 |
| **여러 자산 묶음** | **플러그인** + 마켓플레이스 | 스킬·서브에이전트·훅·MCP 서버·명령을 하나로 |
| **품질 기준** | **eval 스위트** | 데이터셋 + 채점기를 저장소에 포함해 이식 |
| **프로젝트 컨텍스트** | CLAUDE.md + `.claude/rules/` | 경로 스코프 규칙으로 모듈화 |

### 무엇을 버전 관리하는가
- 프롬프트(시스템 프롬프트·스킬 본문), 도구 스키마, eval 데이터셋과 채점기, `.mcp.json`, `.claude/settings.json`, 모델 ID(**별칭이 아니라 고정 스냅샷**)
- **버전 관리하면 안 되는 것**: API 키, 토큰, `~/.claude.json`, `CLAUDE.local.md`, 자격증명이 든 `.mcp.json` 헤더

### 기여(IP contribution)
도구·패턴·수정을 문서화된 채널로 기여할 때는 **메인테이너가 받아들일 수 있는 형태**로 준비한다 — 재현 가능한 예제, eval 결과, 문서, 자격증명 제거.

## 7. AI 생성 코드에 대한 보정된 신뢰

공식 학습 목표(모듈 3): *"AI 생성 코드를 읽고 보정된 신뢰로 검토하며, 잘못된 판단의 비용이 큰 곳에 인간 검토 게이트를 둔다"*

| 위험 수준 | 검토 강도 | 권한 모드 |
| --- | --- | --- |
| 국소적·가역적(테스트 파일 편집) | 가볍게 | `acceptEdits` |
| 로직 변경, 의존성 추가 | 정독 + 테스트 | `default`(Manual) |
| 마이그레이션, 보안 경계, 인프라 | **필수 인간 게이트** | `plan` → 승인 → 실행 |
| 격리된 컨테이너 안의 실험 | 최소 | `bypassPermissions` |

Claude Code in Action의 원칙: **"감독하지 않은 실행은 안 본 만큼에 비례해서 검증하라"**, 그리고 **"훅으로 실제 테스트 결과에 턴을 게이팅하라"**.

### 게이트 구현 수단
| 수단 | 강제력 |
| --- | --- |
| 권한 규칙 `deny` | **강제** |
| `PreToolUse` 훅 exit 2 | **강제** (allow 규칙보다 우선) |
| `Stop` 훅으로 테스트 실패 시 턴 차단 | **강제** |
| plan mode | 편집 차단 |
| CLAUDE.md 지침 | 권고일 뿐 |
| PR 리뷰 / CODEOWNERS | 조직 프로세스 |

## 8. 엔터프라이즈 통합과 경계

공식 학습 목표: *"엔터프라이즈 시스템 연결, 규제 고객이 수용할 인증 패턴, 보안 검토를 통과할 스코프"* / *"데이터·identity 경계를 보안·컴플라이언스 검토가 견딜 수 있게"*

| 경계 | 수단 |
| --- | --- |
| **데이터 경계** | 워크스페이스 분리(테넌트당 1개), 데이터 레지던시(`inference_geo`), ZDR |
| **Identity 경계** | 워크스페이스 범위 API 키, MCP OAuth, `headersHelper`로 단기 토큰, 최소 권한 |
| **시크릿** | 환경변수 주입, `.gitignore`, 자격증명을 `.mcp.json`에 쓰지 않기 |
| **감사** | Compliance API / Activity Feed, `request-id` 로깅, CloudTrail(AWS) |
| **인증 패턴** | OAuth 2.0(DCR 또는 사전 등록), 사내 SSO는 `headersHelper` |

> 규제 고객이 가장 자주 묻는 것: **데이터가 어디로 가는가 / 누가 접근할 수 있는가 / 무엇이 로그에 남는가 / 얼마나 보관되는가.** 이 네 가지에 답할 수 있게 설계한다.
