# D1. 에이전트와 워크플로 (14.7%)

> 세부: 에이전트 아키텍처 4.5% / Claude로 에이전트 구축 5.3% / 에이전트 패턴·프레임워크 4.9%

## 1. 워크플로 vs 에이전트

| | 워크플로 | 에이전트 |
| --- | --- | --- |
| 제어 흐름 | **코드가 미리 정한 경로**를 따름 | **모델이 스스로** 다음 단계를 결정 |
| 예측 가능성 | 높음 | 낮음 |
| 디버깅 | 쉬움 | 어려움 |
| 적합한 문제 | 단계가 정해져 있고 반복적인 작업 | 단계 수·경로를 미리 알 수 없는 개방형 작업 |

**원칙**: 가장 단순한 해법부터 시작한다. 단일 LLM 호출로 충분하면 에이전트를 만들지 않는다. 에이전트는 **복잡성이 실제로 가치를 낼 때만** 도입한다.

### 대표 워크플로 패턴
| 패턴 | 설명 |
| --- | --- |
| **프롬프트 체이닝** | 출력 → 다음 호출의 입력. 중간 결과를 검사·로깅·분기할 수 있다. 가장 흔한 형태는 **자기 수정**(초안 → 검토 → 개선) |
| **라우팅** | 입력을 분류해 전문화된 경로로 보낸다 (예: 간단한 질의는 Haiku, 복잡한 건 Opus) |
| **병렬화** | 독립 하위 작업을 동시에 실행 후 집계 (sectioning) 또는 같은 작업을 여러 번 실행해 투표 (voting) |
| **오케스트레이터-워커** | 리드 모델이 작업을 쪼개 워커에 위임하고 결과를 합친다 |
| **평가자-최적화** | 생성 → 평가 → 피드백 반영을 반복 |

> 최신 모델은 적응형 사고와 서브에이전트 오케스트레이션으로 **대부분의 다단계 추론을 내부적으로 처리**한다. 명시적 체이닝은 중간 출력을 꼭 봐야 할 때만 쓴다.

## 2. 에이전트 루프

```
프롬프트 수신 → 평가/응답 → 도구 실행 → 결과 피드백 → (반복) → 최종 응답
```

개념적으로는 **gather context → take action → verify work → repeat**.

### Messages API로 직접 구현할 때

```python
while True:
    response = client.messages.create(model=..., tools=tools, messages=messages)
    if response.stop_reason == "tool_use":
        tool_results = execute_tools(response.content)
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": tool_results})
    else:
        break
```

주의할 점:
- `stop_reason`을 **모두 분기 처리**한다 (`end_turn` / `max_tokens` / `tool_use` / `pause_turn` / `refusal` / `model_context_window_exceeded`) → [[02 Claude API 메커니즘]]
- 서버 도구 루프는 `pause_turn`을 낼 수 있다 → 어시스턴트 응답을 그대로 다시 보내 이어간다
- thinking 블록은 **받은 그대로** 재전송해야 한다(편집·재정렬·필터링 시 400)
- **Tool Runner**를 쓰면 이 루프를 SDK가 대신 돌린다

## 3. Agent SDK

Claude Code의 에이전트 루프를 내 애플리케이션에 임베드한다. TypeScript(`@anthropic-ai/claude-agent-sdk`), Python(`claude_agent_sdk`) 모두 **Claude Code 바이너리를 번들**한다.

### 루프 단계와 메시지

| 단계 | 산출 메시지 |
| --- | --- |
| 1. 프롬프트 수신 | `SystemMessage` (subtype `"init"`) — 세션 메타데이터 |
| 2. 평가·응답 | `AssistantMessage` — 콘텐츠 블록 단위(텍스트/도구 호출) |
| 3. 도구 실행 | `UserMessage` — 도구 결과 |
| 4. 반복 | **1회 왕복 = 1 turn** |
| 5. 결과 반환 | `ResultMessage` — 최종 텍스트·토큰 사용량·비용·`session_id` |

그 외 `StreamEvent`(부분 메시지 활성화 시), `SystemMessage` subtype `compact_boundary`/`informational`/`worker_shutting_down`.

### 종료 상태 (`ResultMessage.subtype`)

| subtype | 의미 | `result` 필드 |
| --- | --- | --- |
| `success` | 정상 완료 | O |
| `error_max_turns` | maxTurns 초과 | X |
| `error_max_budget_usd` | 예산 초과 | X |
| `error_during_execution` | API 오류·취소 | X |
| `error_max_structured_output_retries` | 구조화 출력 검증 재시도 초과 | X |

`stop_reason`은 마지막 모델 응답이 멈춘 이유(`end_turn` / `max_tokens` / `refusal`).

### 루프 제어 옵션

| 옵션 | 기본값 |
| --- | --- |
| `max_turns` / `maxTurns` — 도구 사용 턴 상한 | 무제한 |
| `max_budget_usd` / `maxBudgetUsd` — 누적 비용 상한(**서브에이전트 비용 포함**) | 무제한 |
| `effort` — `low`/`medium`/`high`/`xhigh`/`max` | 모델 기본값 |
| `permission_mode` — `default`/`acceptEdits`/`plan`/`auto`/`dontAsk`/`bypassPermissions` | `default` |
| `allowed_tools` / `disallowed_tools` | — |
| `setting_sources` — CLAUDE.md·스킬·훅 로드 범위 | — |

> **프로덕션 에이전트는 예산 상한 설정이 기본**. 예산 초과 시 서브에이전트 생성이 `Budget limit reached`로 실패하고 백그라운드 서브에이전트도 중단된다.

### 내장 도구

| 카테고리 | 도구 |
| --- | --- |
| 파일 | `Read`, `Edit`, `Write` |
| 검색 | `Glob`, `Grep` |
| 실행 | `Bash` |
| 웹 | `WebSearch`, `WebFetch` |
| 탐색 | `ToolSearch` |
| 오케스트레이션 | `Agent`, `Skill`, `AskUserQuestion`, `TaskCreate`, `TaskUpdate` |

**병렬 실행**: 읽기 전용 도구(`Read`/`Glob`/`Grep`, `readOnlyHint`가 붙은 MCP 도구)는 동시 실행, 상태 변경 도구(`Edit`/`Write`/`Bash`)는 순차 실행. 커스텀 도구는 기본 순차 → `readOnlyHint`로 병렬 허용.

### 컨텍스트와 세션
- 컨텍스트는 턴 사이에 **초기화되지 않고 누적**된다. 시스템 프롬프트·도구 정의·CLAUDE.md처럼 고정된 부분은 자동으로 **프롬프트 캐시**된다
- 한계에 가까워지면 **자동 압축**되고 `compact_boundary` 메시지가 나온다. 압축은 오래된 메시지를 요약으로 대체하므로 **영구 규칙은 초기 프롬프트가 아니라 CLAUDE.md에** 둔다
- `ResultMessage.session_id`로 resume/fork. 스테이트리스 호스트는 `session_store` 어댑터로 외부 저장

### 훅
`PreToolUse`(입력 검증·위험 명령 차단), `PostToolUse`(감사·부수효과), `UserPromptSubmit`(컨텍스트 주입), `Stop`(결과 검증·상태 저장), `SubagentStart`/`SubagentStop`, `PreCompact`(트랜스크립트 아카이브).
훅은 **애플리케이션 프로세스에서 실행되어 컨텍스트를 소모하지 않고**, `PreToolUse`가 거부하면 도구 호출 자체가 막힌다.

## 4. 서브에이전트

### 왜 쓰는가
- **컨텍스트 보존**: 대용량 탐색·로그가 메인 대화에 남지 않고 요약만 돌아온다
- **제약 강제**: 도구 화이트리스트
- **비용 절감**: 저비용 모델로 라우팅
- **행동 전문화**: 도메인별 시스템 프롬프트

### 언제 쓰고 언제 안 쓰는가
| 위임 | 직접 처리 |
| --- | --- |
| 대용량 출력(테스트·로그·문서 검색) | 잦은 반복 피드백 |
| 독립 병렬 리서치 | 단계 간 큰 컨텍스트 공유 |
| 도구 제약 필요 | 단일 파일 편집 등 단순 작업 |
| 저비용 모델로 충분 | 레이턴시가 중요 |

> 최신 Opus 계열은 **서브에이전트를 과다 사용**하는 경향이 있다. 시스템 프롬프트로 "병렬 실행 가능 / 격리 컨텍스트 필요 / 독립 워크스트림일 때만 위임"이라고 명시하면 조정된다.

### 상속 관계
서브에이전트는 **자신의 시스템 프롬프트 + 위임 메시지 + CLAUDE.md 계층**만 받고, **메인 대화 히스토리·이전 스킬·auto memory는 받지 않는다**. 예외는 fork(전체 대화 상속).

## 5. Managed Agents

| 항목 | 내용 |
| --- | --- |
| 정의 | 완전 관리형 에이전트 인프라. 영구 이벤트 기록을 갖춘 **상태 유지 세션** |
| 구성 흐름 | 에이전트 설정(agent-setup) → 도구(tools) → 도구 권한(permission-policies) → 스트리밍·이벤트 → Sessions API |
| 청구 | 토큰 + **세션 런타임 시간당 $0.08**(`running` 상태만) |
| 미적용 수정자 | Batch API 할인, 파트너 클라우드 가격 |
| 속도 제한 | 생성 엔드포인트 300 RPM / 읽기 엔드포인트 1,200 RPM (Messages API 제한과 별개) |

**선택 기준**: 직접 턴과 도구 루프를 구성하려면 **Messages API**, 호스팅된 상태 유지 세션이 필요하면 **Managed Agents**, Claude Code의 코딩 도구 세트를 그대로 쓰려면 **Agent SDK**.

## 6. 자율성과 안전성

가이드 없이 두면 모델이 파일 삭제·force push·외부 게시 같은 **되돌리기 어려운 행동**을 할 수 있다. 시스템 프롬프트로 명시하는 것이 권장 패턴:

```text
행동의 가역성과 영향 범위를 고려하라. 파일 편집·테스트 실행 같은 국소적·가역적 행동은
자유롭게 하되, 되돌리기 어렵거나 공유 시스템에 영향을 주거나 파괴적인 행동은
먼저 사용자에게 확인하라.
- 파괴적: 파일/브랜치 삭제, DB 테이블 드롭, rm -rf
- 되돌리기 어려움: git push --force, git reset --hard, 배포된 커밋 amend
- 외부에 보임: 코드 푸시, PR/이슈 코멘트, 메시지 발송, 공유 인프라 수정
장애물을 만났을 때 파괴적 행동을 지름길로 쓰지 말 것(--no-verify 등).
```

실제 강제력은 프롬프트가 아니라 **권한 규칙(deny)과 PreToolUse 훅**에서 나온다. → [[07 보안과 안전]]

## 7. 장기 실행 작업 설계

- 모델은 한 번에 다 하기보다 **점진적 진행 + 상태 추적**에 강하다
- 리서치: ① 명확한 성공 기준 제시 ② 여러 소스 교차 검증 ③ 가설 트리/리서치 노트 파일로 진행 상황 영속화
- 컨텍스트 인식 기능이 있는 모델은 남은 컨텍스트를 인지하고 작업을 배분한다
- 상태를 **메모리 도구나 파일로 오프로드**하면 압축·컨텍스트 편집 후에도 이어갈 수 있다 → [[05 프롬프트와 컨텍스트 엔지니어링]]
