## 3. 자주 헷갈리는 쌍

### stop_reason vs HTTP 오류
`stop_reason`은 **HTTP 200 성공 응답의 일부**, 오류는 **4xx/5xx**. `max_tokens`는 오류가 아니라 "잘렸다"는 신호다.

### 429의 두 종류
| | 속도 제한 | 지출 상한 |
| --- | --- | --- |
| `retry-after` 헤더 | **있음** | **없음** |
| `error_code` | — | `enforced_spend_limit_reached` |
| 재시도 | 유효 | 액세스 재개까지 계속 실패 |

### 클라이언트 도구 vs 서버 도구
실행 위치가 기준. 서버 도구(`web_search`, `code_execution` 등)는 내 코드가 실행하지 않는다. **토큰 카운팅 API는 서버 도구를 지원하지 않는다**(advisor 제외).

### effort vs extended thinking
`effort`는 추론 깊이(비용/지연 트레이드오프), extended thinking은 `thinking` 블록 생성 여부. **서로 독립**. 4.7 이후 모델은 `enabled`를 거부하고 `adaptive`만 받는다.

### compaction vs context editing
| | 압축 | 컨텍스트 편집 |
| --- | --- | --- |
| 방식 | 대화를 **요약**으로 대체 | 특정 블록을 **선택 삭제** |
| 위치 | 기본 전략 | 세밀 제어가 필요할 때 |
| 캐시 | 요약 시점에 무효화 | 도구 결과 지우기는 무효화, 사고 유지 시 보존 |

### ITPM에 포함되는 것
`input_tokens` ✓, `cache_creation_input_tokens` ✓, **`cache_read_input_tokens` ✗**(대부분의 모델). → 캐싱이 실질 처리량을 늘린다.

### `usage.input_tokens`의 의미
**마지막 캐시 브레이크포인트 이후의 토큰만** 센다.
`총 입력 = cache_read + cache_creation + input_tokens`

### text_delta vs input_json_delta
`text_delta`는 바로 이어붙이면 되지만, `input_json_delta`는 **부분 JSON 문자열**이라 `content_block_stop` 후에 파싱해야 한다.

### 직접 vs 간접 프롬프트 인젝션
직접 = **사용자가 공격자** / 간접 = **사용자는 신뢰 가능, 제3자 콘텐츠가 공격자**. 간접 방어의 1순위는 "신뢰할 수 없는 콘텐츠를 `tool_result` 블록에만 넣기".

### Messages API vs Managed Agents vs Agent SDK
| | 특징 |
| --- | --- |
| Messages API | 턴과 도구 루프를 직접 구성 |
| Managed Agents | 호스팅된 **상태 유지 세션** + 영구 이벤트 기록, 런타임 과금 |
| Agent SDK | Claude Code 에이전트 루프를 내 앱에 임베드 |

## 4. 꼭 기억할 정책·제약

- **어시스턴트 프리필**은 Claude 4.6 이후 모델에서 미지원 → 400
- **thinking 블록은 받은 그대로 재전송**해야 한다. 편집·재정렬·필터링 시 400
- **강제 도구 사용**(`tool_choice: any`/`tool`)은 Opus 5.5 / Fable 5.1 / Mythos 5.1에서 미지원
- **Files API 업로드 파일은 다운로드 불가**. 스킬·코드 실행이 생성한 파일만 다운로드
- **업로드 파일은 워크스페이스 전체 공유** — 최종 사용자에게서 `file_id`를 받지 말 것
- **구조화된 출력 스키마에 PHI를 넣지 말 것** (스키마는 24시간 별도 캐시)
- **배치에서 `stream`·`speed`·`max_tokens: 0`은 검증 오류**
- **토큰 카운팅은 서버 도구·MCP 커넥터·`url`/`file` 소스를 지원하지 않는다**
- 권한 규칙 평가 순서는 **deny → ask → allow**, 훅 exit 2는 allow보다 우선

## 5. 시험 전 자가 점검 질문

1. `stop_reason: "pause_turn"`을 받으면 정확히 무엇을 다시 보내야 하는가?
2. 429에 `retry-after`가 없다면 원인이 무엇이고 재시도가 통하는가?
3. 캐시 히트가 200k인데 `usage.input_tokens`가 50으로 나온다. 총 입력 토큰은?
4. 멀티턴 비전 앱에서 요청 페이로드가 계속 커진다. 무엇을 바꾸는가?
5. `tool_use` 스트리밍에서 `delta`를 그대로 `JSON.parse`하면 왜 실패하는가?
6. Batch API에서 `errored` / `expired` 결과는 과금되는가?
7. 4.6 모델용으로 짠 프리필 코드를 4.7로 올렸다. 어떤 오류가 나고 어떻게 고치는가?
8. strict 도구 8개에 각각 선택 파라미터 4개가 있다. 어떤 한도에 걸리는가?
9. 이메일 본문을 Claude에게 넘길 때 어느 블록에 어떤 형태로 넣어야 하는가?
10. 1000×1000 이미지 1장의 비주얼 토큰 수는?
   *(답: ⌈1000/28⌉² = 36² = 1296)*
