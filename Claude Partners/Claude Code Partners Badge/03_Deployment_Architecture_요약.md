## Lesson 1. 배포 결정 프레임워크

> **하나의 결정이 엔게이지먼트 전체를 좌우한다.**

### 왜 되돌리기 어려운가

배포 경로에 따라 누가 청구하는지, 어떻게 인증하는지, 사용량 데이터가 어디에 쌓이는지, 어떤 기능이 존재하는지가 정해진다.

- 조달팀은 청구 경로를 기준으로 계약한다.
- 보안팀은 인증 모델을 검토한다.
- 재무팀은 비용 추적 체계를 기준으로 부서별 비용 배분(chargeback)을 설계한다.

롤아웃 후에 경로를 바꾸면 이 세 작업을 전부 다시 해야 한다. 그래서 30일 활성화 계획에서는 이 추천을 **킥오프 전(Day -14 ~ Day 0)**에 보안 질의서, 조직 설정과 함께 확정한다. 한번 들어가면 돌아 나오기 어려운 문으로 다뤄야 한다.

> **원칙:** 경로는 고객의 기존 클라우드 약정과 컴플라이언스 입장이 결정한다. 컨설턴트의 역할은 고객이 기본값으로 정해버리기 전에 이것을 먼저 드러내는 것이다.

### 4가지 경로 (CLI는 모두 동일, 주변 환경이 다름)

| 경로 | 특징 |
|---|---|
| **Claude for Enterprise (직접)** | Anthropic 권장 기본값. 좌석 기반 계약, SSO·도메인 캡처, 역할 기반 권한, 관리형 정책 설정, Compliance API. **웹 Claude가 포함된 유일한 경로이자 ZDR 적용이 가능한 유일한 경로.** 인증은 Claude.ai SSO, 비용 추적은 사용량 대시보드 |
| **Amazon Bedrock** | 모델 트래픽이 고객 AWS 계정 안에 머문다. AWS를 통한 종량제 청구라 기존 AWS 약정 소진에 반영된다. IAM/Bedrock API 키 인증, CloudTrail 감사, Cost Explorer 비용 추적, Bedrock Guardrails 콘텐츠 필터링. 계정·리전별 모델 활성화는 고객이 직접 관리 |
| **Google Vertex AI** | GCP 네이티브. GCP 청구, GCP 자격증명/ADC 인증, IAM, Cloud Audit Logs. Model Garden에서 프로젝트별로 모델 접근을 요청하며 **승인까지 24~48시간**이 걸릴 수 있다. 글로벌·멀티 리전·리전 엔드포인트 지원 |
| **Microsoft Foundry** | Azure 네이티브. Azure 청구, API 키/Entra ID 인증, RBAC, Azure Monitor. Foundry 포털에서 모델 배포를 생성한다. **Bedrock·Vertex와 달리 요청이 Anthropic이 운영하는 인프라로 라우팅된다** → 데이터 레지던시 논의가 달라진다 |

### 결정 요인 4가지 (이 순서로 질문)

1. **클라우드 약정은 어디에 있는가?** – AWS EDP, GCP CUD, Azure MACC 같은 약정 소진 계약이 해당 클라우드 경로로 가장 강하게 끌어당긴다. IT뿐 아니라 조달팀에 물어볼 것.
2. **조달은 어떻게 구매하길 원하는가?** – 새 Anthropic 계약(좌석 기반) vs 기존 클라우드 마켓플레이스(종량제). 마켓플레이스 지출은 며칠, 신규 벤더는 몇 달이 걸리기도 한다. 아키텍처만큼 일정에도 영향을 준다.
3. **컴플라이언스가 무엇을 요구하는가?** – ZDR이 필요하면 Enterprise 직접만 가능. 트래픽이 자사 클라우드 테넌시·리전 안에 있어야 하면 Bedrock 또는 Vertex.
4. **사용자와 예산은 누가 관리하는가?** – Enterprise 직접은 좌석 관리, 관리형 설정, 사용량 대시보드를 기본 제공한다. 클라우드 경로는 IAM과 클라우드 비용 도구로 직접 구성하거나 LLM 게이트웨이를 추가해야 한다.

### 명시적으로 말해야 할 트레이드오프

- **클라우드 경로:** 고객이 이미 관리하는 경계·도구 안에서 운영된다. 대신 웹 Claude가 없고, ZDR이 없으며, 몇 가지 기능 격차가 있다. 특히 두 가지를 직접 챙겨야 한다.
  - **모델 버전 고정**: 고정하지 않은 별칭은 최신 릴리스보다 늦은 기본값으로 연결되거나, 계정에서 활성화되지 않은 모델을 가리켜 오류가 날 수 있다 → 롤아웃 전에 관리형 설정에서 버전을 고정할 것
  - **사용량 대시보드 구축**: Cost Explorer, GCP Billing, Azure Cost Management 또는 게이트웨이로 구성해야 한다
- **Enterprise 직접:** 전체 기능을 Anthropic이 관리한다. 대신 신규 벤더 계약이 필요하고, 약정 소진이 아닌 좌석 기반 가격이며, 모델 트래픽이 고객 테넌시가 아닌 Anthropic 플랫폼으로 간다.

> 트레이드오프를 명시적으로 말하는 것이 '추천'과 '선호'를 구분 짓는다.

### 경로별 킥오프 전(Day -14) 체크리스트

| 경로 | 핵심 | 할 일 |
|---|---|---|
| Enterprise 직접 | 아이덴티티 설정이 가장 오래 걸림 | IdP팀과 SSO·도메인 캡처 설정, 좌석·역할 매핑, 관리형 정책 적용, 필요 시 ZDR 활성화 요청(조직 단위 확인) |
| Bedrock | 대부분 당일 처리 가능 | AWS 계정별 사용 사례 양식 제출(즉시 접근), 모델 호출·추론 프로필용 IAM 정책, 대상 리전에서 모델 활성화, 설치 전 모델 ID 고정 |
| Vertex AI | **Day 1에 접근 요청 제출** | Vertex AI API 활성화, Model Garden 접근 요청(24~48시간), 리전 쿼터 확인, 모델 ID 고정 |
| Foundry | 배포 프로비저닝, 버전 고정 | Foundry 리소스 생성, 자동 업데이트가 아닌 고정 버전으로 모델 배포, Entra ID 역할/API 키 처리 합의, 설정에 배포 이름 고정 |

### 시나리오: Meridian Capital (금융사, 개발자 800명)

| 상황 | 권장 답 |
|---|---|
| 1. 30분 디스커버리 콜에서 가장 먼저 확인할 것 | **클라우드 약정과 구매 경로** (EDP/CUD/MACC 여부, 마켓플레이스 vs 신규 계약). 좌석 수나 IDE 표준은 나중 문제 |
| 2. 3년 AWS EDP가 남아 있고 CFO는 AI 비용을 여기에 반영하길 원함. 보안 검토는 대기 중 | **Bedrock 추천, 단 보안 검토 결과에 따라 바뀔 수 있다고 명시** |
| 3. CISO: "Bedrock에서도 ZDR이 되나요?" | **"안 됩니다. Bedrock에서는 보존 정책이 AWS를 따릅니다."** ZDR은 Enterprise 직접 전용이다 |
| 4. CIO: "직접 계약 대비 무엇을 포기하나요?" | **기능 격차를 구체적으로 말한다**: 웹 Claude 없음, ZDR 없음, WebSearch 불가, 모델 버전 고정은 고객 책임. 서명 전에 1페이지 격차 메모를 제공 |

### Decision Doc 기여: 고객 프로필과 경로 추천

1. 샘플 고객 정의(산업, 개발자 수, 주 클라우드, 약정 계약 1개)
2. 결정 요인 4가지에 한 문장씩 답하기
3. 추천: 경로 하나 + 근거 두 문장 + 판단을 바꿀 단 하나의 조건
4. 해당 경로의 킥오프 전 장애 요인을 담당자, 소요 시간과 함께 나열

## Lesson 2. 기능 격차와 고객에게 알릴 사항

> **계약 시점에 알린 격차는 컨설팅이다. 3주차에 발견된 같은 격차는 당신 이름이 붙은 결함이다.**

### 타이밍이 결과를 결정한다

모든 격차는 결국 발견된다. 문제는 누가, 언제 발견하느냐다.

- 1주차: 챔피언이 "그 기능 어디 갔어요?"라고 묻는다
- 2주차: CoE가 "메트릭 대시보드가 왜 비어 있죠?"라고 묻는다
- Day 30: 최대 격차 리포트가 계약 때부터 알던 항목이거나, 처음 듣는 항목(당신 이름이 붙은)이 된다

→ 경로 추천과 함께 **서명 전에 1페이지 격차 메모**를 전달하는 것이 가장 저렴한 보험이다. SOW에서 범위 제외 항목을 명시하는 것과 같은 원리로, 동의한 항목에는 아무도 이의를 제기하지 않는다.

### 메모에 넣을 6가지 격차

| 대상 | 격차 | 내용 |
|---|---|---|
| Bedrock | **WebSearch 불가** | 내장 WebSearch 도구가 동작하지 않는다. 문서 실시간 조회에 의존하는 팀은 승인된 MCP 대안을 킥오프 전에 준비해야 한다 |
| 모든 클라우드 경로 | **웹 Claude 미포함** | Teams·Enterprise 직접만 웹을 포함한다. 비즈니스 이해관계자에게 채팅 화면이 없다는 사실은 임원이 데모를 요청할 때 처음 드러난다 |
| 모든 클라우드 경로 | **Anthropic ZDR 미적용** | 보존 정책은 고객이 이미 관리하는 클라우드 제공자 정책을 따른다. "통제가 없다"가 아니라 "통제 주체가 다르다"로 설명할 것 |
| 모든 클라우드 경로 | **모델 버전은 고객 책임** | `sonnet` 같은 별칭은 릴리스보다 늦거나 활성화되지 않은 모델을 가리킬 수 있다. 백그라운드 작업도 저렴한 Haiku급이 아닌 주 모델을 기본으로 쓴다 → 롤아웃 전 버전 고정 |
| 모든 클라우드 경로 | **텔레메트리 기본 꺼짐** | Anthropic 메트릭, 오류 보고, `/feedback`이 기본 비활성이다(`/feedback`은 로컬 번들로 저장). CoE가 매주 보는 도입 지표는 OTel이나 게이트웨이로 수집해야 한다 |
| Vertex | **Vertex 고유 주의사항** | Model Garden 승인 24~48시간 / MCP 도구 검색이 기본 꺼져 있어 명시적으로 켜야 함(안 켜면 큰 도구 카탈로그가 처음에 전부 로드됨) / 프롬프트 캐싱은 리전마다 지원이 다름(Bedrock도 동일). 캐시 수치가 0이면 리전을 확인 |

### 격차 메모 작성법 (리스크 대장이 아니라 1페이지)

각 줄을 같은 구조로 쓴다.

1. **격차 명시**: 이 경로에서 없거나 제한되는 기능
2. **시점 명시**: 고객이 언제, 누가, 어떤 회의에서 마주칠지
3. **완화책을 먼저**: 이미 준비된 계획을 제약보다 앞에 둔다

예: "Bedrock에서는 WebSearch를 쓸 수 없습니다. 플랫폼 문서팀이 1주차에 마주칠 텐데, 킥오프 전에 승인된 MCP 대안을 준비하겠습니다." → 준비된 것으로 읽힌다. 단순 기능 비교표는 계약을 미룰 이유로 읽힌다.

### 시나리오: Northgate Logistics (Bedrock 계약)

| 상황 | 권장 답 |
|---|---|
| 1. CTO: "이 목록을 보안팀에 보여주면 계약이 멈춰요. 줄일 수 있나요?" | **모든 항목을 유지하되 완화책 중심으로 재구성**하고, 보안팀 설명을 직접 맡겠다고 제안 |
| 2. 2주차, 20명이 보는 채널에 "WebSearch가 안 돼요. 설치가 잘못된 건가요?" | **메모의 해당 줄과 준비된 MCP 대안을 링크로 답변** (지원 티켓을 열거나 개인 claude.ai 계정 사용을 권하지 말 것) |
| 3. CoE 리뷰: "사용량 데이터가 어디 있죠?" | **기본 설정을 설명하고 해결책을 제안**: Bedrock은 Anthropic 텔레메트리가 기본 꺼져 있으므로 OTel(사용 이벤트), Cost Explorer(비용), 또는 게이트웨이로 수집 |

## Lesson 3. 사내 프록시 설정

> **Day 1의 성패는 프록시에서 갈린다.** 모든 엔터프라이즈 활성화의 첫 지원 티켓은 네트워크 티켓이다.

### 프록시 vs LLM 게이트웨이 (함께 쓰는 경우도 많음)

| | 사내 프록시 (이 레슨) | LLM 게이트웨이 (Lesson 4) |
|---|---|---|
| 역할 | 트래픽을 회사 밖으로 내보낸다 | 모델 트래픽에 무슨 일이 일어날지 통제한다 |
| 내용 | 기존 네트워크 경계: HTTP/HTTPS 프록시, TLS 검사, 방화벽 허용 목록 | 중앙 인증, 사용량 추적, 예산, 감사 |
| 설정 | 표준 프록시 환경변수 | Base URL 재정의 |
| 소유 | 네트워크·보안팀 | 고객이 의도적으로 배포하는 서비스 |

### 프록시 환경변수

```bash
export HTTPS_PROXY=https://proxy.client.com:8080
export HTTP_PROXY=http://proxy.client.com:8080     # HTTPS 엔드포인트가 없을 때
export NO_PROXY="localhost,.client.com,169.254.169.254"
# 기본 인증이 필요하면 URL에 포함 (시크릿 매니저에서 가져올 것, 하드코딩 금지)
export HTTPS_PROXY=http://user:pass@proxy.client.com:8080
```

- 프록시 환경변수는 **OS 레벨**이라 Claude Code 설정 파일로 지정할 수 없다. 조직 전체에 배포하려면 **MDM**을 쓴다(macOS: Jamf·Kandji, Windows: 레지스트리 정책).
- **SOCKS 프록시는 미지원**이다.
- **NTLM·Kerberos 인증은 직접 지원하지 않으므로** 이를 처리하는 LLM 게이트웨이로 해결한다.

### TLS 검사와 인증서 신뢰

"self-signed certificate in chain" 오류는 프록시가 **설계대로 동작하고 있다는 뜻**이다. Zscaler, Netskope 같은 TLS 검사 프록시는 회사 루트 CA로 트래픽을 다시 서명한다. Claude Code는 기본적으로 OS 신뢰 저장소를 쓰므로 잘 관리된 기기에서는 대부분 그냥 동작한다.

안 될 때는 **인증서 검증을 끄지 말고** 루트 인증서를 직접 지정한다. 검증을 끄자는 제안은 고객 보안 검토에서 당연히 탈락한다.

```bash
export NODE_EXTRA_CA_CERTS=/etc/ssl/corp-root-ca.pem
export CLAUDE_CODE_CERT_STORE=system
# mTLS 환경
export CLAUDE_CODE_CLIENT_CERT=/path/to/client-cert.pem
export CLAUDE_CODE_CLIENT_KEY=/path/to/client-key.pem
```

### 허용 목록 (첫 미팅에서 도메인별 근거와 함께 전달)

| 분류 | 도메인 | 설명 |
|---|---|---|
| 모델·API | `api.anthropic.com` | 직접 경로의 API 요청 + **모든 경로에서 WebFetch 도메인 안전성 검사**. Bedrock이라도 이걸 막으면 WebFetch가 실패한다(설정에서 사전 검사를 끄지 않는 한) |
| 인증 | `claude.ai`, `platform.claude.com` | claude.ai / Console 계정 인증. 클라우드 경로는 제공자 쪽에서 인증하므로 주로 직접 경로에서 필요 |
| 배포 | `downloads.claude.ai` | 설치 프로그램, 자동 업데이트, 플러그인. 자체 아티팩트 레지스트리로 배포하면 생략 가능 |
| 클라우드 경로 | 제공자 엔드포인트 | 대개 이미 열려 있음. Anthropic 텔레메트리는 기본 꺼짐. 최종 상태는 `/status`로 확인 |

→ 목록을 바로 건네면 같은 주에 승인되고, 그렇지 않으면 3주짜리 변경 요청이 된다.

### 관리형 설정 (managed-settings.json)

"모든 개발자가 올바른 설정을 쓰게 하려면?"에 대한 답.

- 설정 계층의 **최상위**에 있어 사용자·프로젝트 설정으로 덮어쓸 수 없다.
- 권한 잠금, 허용 MCP 서버 강제, SSO 로그인 필수화, 최소 버전 고정 등에 쓴다.
- **배포 방법 3가지** (모두 관리자 권한 필요):
  1. 서버 관리형: Anthropic 관리 콘솔(Enterprise 전용)
  2. MDM/OS 레벨: macOS plist, Windows 레지스트리(Jamf, Kandji 등)
  3. 파일 기반: OS의 시스템 디렉터리에 managed-settings.json 배치

### 시나리오: Halvern Bank, 40대 터미널이 모두 멈춤

| 상황 | 권장 답 |
|---|---|
| 1. 모든 첫 프롬프트가 무한 로딩 | **네트워크팀을 바로 통화에 참여시켜** 프록시 경유 여부와 TLS 검사 여부를 확인 (일괄 재설치는 의미 없음) |
| 2. 프록시 확인됨(`proxy.halvern.net:8080`). 40대에 어떻게 적용? | **MDM으로 `HTTPS_PROXY`와 `NO_PROXY` 배포** (채팅방에 명령어를 올리거나 SOCKS를 쓰는 것은 오답) |
| 3. "self-signed certificate" 오류. 누군가 TLS 검증을 끄는 플래그를 제안 | **거절하고 `NODE_EXTRA_CA_CERTS`로 회사 루트 CA를 지정** |
| 4. 네트워크팀이 허용할 도메인을 물음 | **구체적인 도메인 목록과 각각의 근거, 선택적 텔레메트리 엔드포인트와 끄는 방법을 제공** (`*.anthropic.com` 와일드카드나 "그냥 443이에요"는 오답) |

## Lesson 4. LLM 게이트웨이 패턴

> **프록시는 트래픽을 통과시키고, 게이트웨이는 트래픽을 이해한다.**

여러 팀이 모델을 호출하는 엔터프라이즈 고객은 결국 "누가 얼마를 쓰고 있나?"를 묻는다. 프록시는 이 질문에 답할 수 없고, 게이트웨이는 답할 수 있다.

### 게이트웨이만 제공하는 5가지 기능

1. **중앙 인증** – 제공자 자격증명은 플랫폼팀이 한곳에서 관리하고, 개발자는 단기 게이트웨이 토큰만 가진다. 키 교체도 한 번에 처리된다.
2. **팀별 비용 귀속** – 세션 헤더로 요청을 팀 토큰에 매핑한다. 요청 본문 파싱이나 클라우드 청구서 추정 없이 누가 얼마를 썼는지 알 수 있다.
3. **예산 강제** – 팀별 속도 제한과 지출 한도를 모델 호출 *전에* 적용한다. 리포팅이 아니라 강제 기능이다.
4. **모델 라우팅** – 고정된 엔드포인트 뒤에서 제공자·모델 버전을 바꾼다. Bedrock과 Vertex를 하나의 Base URL로 제공할 수 있어 개발자 PC는 바꿀 필요가 없다.
5. **컴플라이언스 감사 로그** – 모든 모델 상호작용을 고객 스택에 기록한다. Anthropic 텔레메트리가 꺼진 클라우드 경로에서는 이 로그가 관측성의 원천이 된다.

### 설정

```bash
# Anthropic API 형식 게이트웨이
export ANTHROPIC_BASE_URL=https://llm-gateway.client.com
export ANTHROPIC_AUTH_TOKEN=team-token-from-gateway

# Bedrock을 게이트웨이 뒤에
export CLAUDE_CODE_USE_BEDROCK=1
export ANTHROPIC_BEDROCK_BASE_URL=https://llm-gateway.client.com/bedrock
export CLAUDE_CODE_SKIP_BEDROCK_AUTH=1

# Vertex를 게이트웨이 뒤에
export CLAUDE_CODE_USE_VERTEX=1
export ANTHROPIC_VERTEX_BASE_URL=https://llm-gateway.client.com/vertex
export CLAUDE_CODE_SKIP_VERTEX_AUTH=1
```

- **skip-auth 플래그**: 게이트웨이가 서버 측에서 자격증명을 주입하므로 Claude Code가 직접 서명하지 않는다. 중앙 인증의 효과가 코드로 드러나는 부분이다.
- 사용자별 교체 토큰은 설정의 **`apiKeyHelper`**로 고객 볼트에서 가져오는 스크립트를 실행한다.
- **필수 인수 조건:** 게이트웨이는 `anthropic-beta`, `anthropic-version` 헤더를 **그대로 전달해야 한다.** 이 헤더를 제거하면 기능이 조용히 저하되고, 트래픽을 직접 확인하기 전까지는 제품 버그처럼 보인다.

### 세션 헤더 (Claude Code가 자동으로 붙임)

| 헤더 | 수준 | 용도 |
|---|---|---|
| `X-Claude-Code-Session-Id` | 세션 | 세션 단위 비용·시간 집계 |
| `X-Claude-Code-Agent-Id` | 서브 에이전트 | 병렬 서브 에이전트별 비용 귀속 |
| `X-Claude-Code-Parent-Agent-Id` | 부모 관계 | 중첩된 에이전트를 하나의 팀 비용으로 합산 |

→ 게이트웨이 토큰을 팀에 매핑하면 팀별 주간 비용, 개발자별 세션 수, 청구서 전 예산 알림을 얻을 수 있다. CoE 메트릭 리뷰와 CFO 보고를 같은 데이터로 해결한다. 비기술 리더는 따로 설정할 필요가 없다(Claude Code가 보내고 게이트웨이가 읽는다).

### 참조 구현: LiteLLM

- Anthropic 게이트웨이 문서의 참조 구현이다(유일한 선택지는 아니다).
- Anthropic Messages 형식과 OpenAI 호환 형식을 모두 통과시킨다.
- 문서: code.claude.com/docs/en/llm-gateway
- ⚠️ **보안 공지: LiteLLM PyPI 1.82.7, 1.82.8 버전은 자격증명 탈취 악성코드에 감염되었다. 설치 금지.** 배포 전에 문서에서 안전한 버전을 확인할 것.

> **포지셔닝 원칙:** 팀이 둘 이상인 엔터프라이즈 고객은 결국 "누가 얼마를 쓰나?"를 묻는다. 첫 청구서에 놀라기 전에 게이트웨이를 먼저 추천하라.

### Decision Doc 기여: 게이트웨이 섹션

1. 게이트웨이 필요 여부 (팀 2개 이상, 비용 배분 요건, 멀티 클라우드 라우팅 중 하나라도 해당되면 필요)
2. 게이트웨이가 앞단에 설 경로와 적용할 skip-auth 플래그
3. 인수 조건: `anthropic-beta`, `anthropic-version` 헤더 전달 → 파일럿 진행 여부(go/no-go) 요건
4. LiteLLM 사용 시 문서와 대조해 버전 확인

## Lesson 5. 데이터 레지던시, 컴플라이언스, ZDR

> **보안 질의서에는 그 자리에서 답하라.**

### 보안 질의서의 3대 질문

1. **"우리 데이터로 모델을 학습하나요?"**
2. **"무엇을, 얼마나 보관하나요?"**
3. **"데이터가 물리적으로 어디로 가나요?"**

### 학습과 보존

- **학습:** 상업 약관(Team, Enterprise, API, 클라우드 경로 모두)에서는 Claude Code에 보낸 코드·프롬프트로 생성형 모델을 학습하지 **않는다.** 유일한 예외는 **명시적 옵트인**(예: Development Partner Program, 조직 관리자가 직접 가입해야 하며 Bedrock·Vertex에서는 불가).
  → "절대 안 합니다"가 아니라 **"명시적으로 옵트인하지 않는 한 안 합니다"**라고 말할 것. 고객이 직접 확인해도 맞는 답이어야 한다.
- **서버 측 보존:** 고객 계약에 따른다. 요금제와 맞지 않을 수 있는 숫자를 단정하지 말고 어카운트팀이나 Anthropic 개인정보 문서에서 확인할 것.
- **로컬 보존:** Claude Code는 세션 기록을 각 개발자 PC의 홈 디렉터리에 **평문으로 캐시**한다(설정으로 변경 가능). 이것은 클라우드가 아니라 **기기 관리** 문제다.

### 경로별 저장 데이터 암호화

| 경로 | 내용 |
|---|---|
| Anthropic 직접 | AES-256 디스크 암호화, 자격 요건을 갖춘 Enterprise 조직은 ZDR 가능 |
| Bedrock | 고객 AWS 계정, AWS 관리 키 AES-256, KMS로 고객 관리 키 가능 |
| Vertex AI | 고객 GCP 프로젝트, Google 관리 키 기본, CMEK 가능 |
| Foundry | **가장 오해가 많은 경로.** Azure 청구·Entra ID·RBAC가 적용되지만, 클라우드별 레지던시 요건이 있으면 데이터 라우팅 경로를 Anthropic에 확인할 것. "데이터가 테넌시를 안 벗어나나?"는 사후가 아니라 경로 결정 단계에서 다뤄야 한다 |

### ZDR (Zero Data Retention), 정확하게

ZDR은 슬로건이 아니라 **적용 범위**다.

- **Claude for Enterprise의 Claude Code에만** 적용된다. Anthropic 어카운트팀이 자격 검토 후 **조직 단위로 활성화**하며, 기본 Enterprise 플랜에 포함되지 않고 클라우드 경로에서는 불가능하다.
- **적용 대상:** Claude Code 세션의 프롬프트와 응답은 실시간 처리 후 저장하지 않는다(법적 요구나 악용 대응은 예외). 비용 통제, 분석, 감사 로그 같은 관리 기능은 계속 동작한다.
- **적용 안 됨:** claude.ai 채팅, Cowork, 좌석 배정 같은 관리 메타데이터, 서드파티 MCP 서버가 처리하는 데이터.
- **비활성화되는 기능**(서버 측 저장이 필요하므로): **웹의 Claude Code, 데스크톱 앱의 원격 세션, `/feedback`.**
- 정책 위반으로 플래그된 세션은 최대 2년간 보존될 수 있다.
- → **ZDR과 웹의 Claude Code는 둘 중 하나를 골라야 한다.**
- ZDR 환경의 분석에는 사용량 지표만 있고 기여도 지표는 없다 → Day 30 스코어카드를 실제로 측정 가능한 지표로 설계할 것.
- 같은 계정이라도 **새 조직마다 별도로 활성화**해야 한다(조직이 여러 개인 엔터프라이즈에서 놓치기 쉬움).

### 레지던시와 인증

- **레지던시는 경로를 따른다.** 리전 통제가 필수라면 클라우드 경로: Bedrock은 AWS 리전 선택, Vertex는 글로벌/멀티 리전/리전 엔드포인트.
- 직접 경로는 Anthropic 지원 국가 기준이며, 특정 리전 처리 보장은 어카운트팀과 논의할 사항이다. 즉석에서 지어내지 말 것.
- **인증 자료는 trust.anthropic.com에서 셀프 서비스로 받을 수 있다:** SOC 2 Type 2, ISO 27001:2022, ISO/IEC 27017·27018, ISO/IEC 42001(AI 관리), CSA STAR Level 2, HIPAA(BAA 가능), GDPR, NIST 800-171, FedRAMP High(Claude for Government), 연간 외부 모의해킹 요약.

> **원칙:** 근거를 댈 수 있는 사실로 답하고, 확인할 한 가지는 명확히 말하고, 보장을 지어내지 말 것. 보안팀은 "리전 보장은 확인해 드리겠습니다"는 용서하지만, 틀린 "네"는 용서하지 않는다.

### 시나리오: Corvane Health CISO의 질문 (코스 최종 관문)

| 질문 | 권장 답 |
|---|---|
| 1. "소스 코드로 모델을 학습하나요?" | **"상업 약관에서는 안 합니다. 명시적으로 옵트인하지 않는 한."** ("익명화한다"는 틀림) |
| 2. "ZDR 없이 Enterprise 직접이면 무엇이 어디에 보존되나요?" | **서버 측 보존 + 각 노트북의 로컬 평문 기록까지 함께 답변.** 선택지 B는 서버 30일, 로컬 기본 30일(설정 가능)로 제시한다. 다만 본문은 서버 보존 기간을 어카운트팀에 확인하라고 하므로, 실제로는 기간을 확인한 뒤 말할 것. "아무것도 저장 안 됨"은 오답 |
| 3. "ZDR도 원하고 웹의 Claude Code도 쓰고 싶어요. 둘 다 되죠?" | **"둘은 충돌합니다. ZDR은 웹 화면을 비활성화하니 신중히 선택하시죠."** |
| 4. "Azure를 쓰니 Foundry로 가면 전부 우리 테넌시에 머물죠?" | **"아닙니다. Foundry는 Anthropic 인프라로 라우팅됩니다."** 테넌시 내 레지던시가 필수라면 Bedrock이나 Vertex |
| 5. "금요일까지 인증서랑 모의해킹 결과 보내주세요." | **"오늘 Trust Center 링크로 보내드리겠습니다."** 회의가 끝나기 전에 링크를 전달 |

### Decision Doc 기여: 컴플라이언스 섹션 (최종)

1. 학습 답변, 로컬 기록을 포함한 보존 답변, ZDR 입장과 트레이드오프
2. 추천 경로의 레지던시 설명과 전달할 인증 자료 목록(출처: Trust Center)
3. 다섯 섹션을 합쳐 문서를 완성하고, 동료가 CISO 역할로 15분간 공격해 보게 한다 → 문서가 답하지 못한 질문이 곧 수정 목록

## 전체 정리

- **경로 결정:** 클라우드 약정 → 구매 경로 → 컴플라이언스 → 관리 주체 순으로 묻는다. 킥오프 전에 확정하는 되돌리기 어려운 결정이다.
- **격차 고지:** 서명 전에 1페이지 메모로 알린다. 각 줄은 격차, 시점, 완화책(완화책 먼저) 구조로 쓴다. 클라우드 경로는 웹 Claude 없음, ZDR 없음, 텔레메트리 꺼짐, 버전 고정 필요. Bedrock은 WebSearch 불가.
- **프록시:** `HTTPS_PROXY`·`NO_PROXY`는 MDM으로 배포하고, TLS 검증은 끄지 말고 `NODE_EXTRA_CA_CERTS`를 쓴다. 근거가 담긴 허용 목록을 건네고, 관리형 설정으로 강제한다.
- **게이트웨이:** 팀이 둘 이상이면 먼저 추천한다. Base URL, 토큰, skip-auth로 설정하고 헤더 전달을 필수로 둔다. 세션 헤더로 팀별 비용 배분이 가능하다.
- **컴플라이언스:** "옵트인하지 않는 한 학습 안 함", 로컬 기록 존재, ZDR은 Enterprise 직접 전용이며 웹과 충돌한다. Foundry는 Anthropic 인프라로 라우팅된다. 인증 자료는 Trust Center에서 받는다.
