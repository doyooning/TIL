## 2. 우선순위 3종 세트

### 설정 우선순위 (높음 → 낮음)
**Managed → Command line(`--settings`) → Project local → Shared project → User**
- 리스트형 키(`permissions.allow` 등)는 **병합**
- 환경변수는 별도 레벨이 아니라 키별로 결정
- 일부 보안 키는 **더 엄격한 값**이 낮은 레벨에서도 이긴다

### 권한 규칙 평가 순서
**deny → ask → allow** (첫 매칭 승, 구체성 무관)
- 어느 스코프의 deny든 다른 스코프의 allow를 이긴다
- 맨 이름 deny(`Bash`)는 도구를 **컨텍스트에서 제거**
- PreToolUse 훅 exit 2 > 모든 allow 규칙 / 훅의 `"allow"` < deny·ask 규칙

### MCP 서버 우선순위
**Managed MCP → Local → Project → User → 플러그인 → claude.ai 커넥터**
같은 이름이면 필드 병합 없이 **통째로 교체**

## 3. 권한 모드 한 줄 요약

| 모드 | 한 줄 |
| --- | --- |
| `default`(Manual) | 읽기만 자동, 나머지는 다 물어봄 |
| `acceptEdits` | 편집 + 기본 파일시스템 명령 자동 |
| `plan` | 탐색만, 소스 편집 금지 |
| `auto` | 분류기 모델이 대신 검토 (Pro/Max/Team 기본) |
| `dontAsk` | 사전 승인된 것만 실행, **물어봐야 할 건 전부 거부** |
| `bypassPermissions` | 전부 허용, **격리 환경 전용** |

**어떤 모드도 자동 승인 안 하는 것**: ask 규칙 매칭 / 조직이 ask로 지정한 커넥터 도구 / `AskUserQuestion`·`requiresUserInteraction` / critical path에 대한 `rm`·`rmdir` / 교차 세션 메시징 안전장치

## 5. 자주 헷갈리는 쌍

### CLAUDE.md vs auto memory
| | CLAUDE.md | auto memory |
| --- | --- | --- |
| 작성자 | 나 | Claude |
| 내용 | 지침·규칙 | 학습·선호·교정 |
| 범위 | 프로젝트/사용자/조직 | 저장소 단위, 머신 로컬 |
| 공유 | git으로 팀 공유 | 공유 안 됨 |

### Skill vs Subagent
| | Skill | Subagent |
| --- | --- | --- |
| 컨텍스트 | **메인 컨텍스트에 로드** | **별도 컨텍스트 창** |
| 반환 | 본문이 대화에 남음 | 최종 요약만 돌아옴 |
| 도구 제한 | `allowed-tools`(그 턴만) | `tools`/`disallowedTools`(영구) |
| 격리 필요 시 | `context: fork` 옵션 사용 | 기본 격리 |

### 서버 도구 vs 클라이언트 도구
실행 위치가 기준. 서버 도구(`web_search`, `code_execution` 등)는 내 코드가 실행하지 않고 결과만 받는다. 단, **클라이언트 도구와 같은 병렬 호출 그룹에 섞이면** 중지 이유 처리를 신경 써야 한다.

### effort vs extended thinking
`effort`는 추론 깊이(비용/지연 트레이드오프), extended thinking은 `thinking` 블록 생성 여부. **서로 독립**.

### compaction vs context editing
| | 압축(compaction) | 컨텍스트 편집 |
| --- | --- | --- |
| 방식 | 대화를 **요약**으로 대체 | 특정 블록을 **선택적으로 삭제** |
| 기본 전략 여부 | **기본** | 세밀 제어가 필요할 때 |
| 위치 | 서버 측(또는 SDK 클라이언트 측) | 서버 측 |
| 캐시 | 요약 시점에 무효화 | 도구 결과 지우기는 무효화, 사고 블록 유지 시 보존 |

### `tool_choice: any` vs `tool`
`any` = 도구 중 아무거나 반드시 / `tool` = 지정 도구 강제. **둘 다 프리필을 쓰므로 자연어 설명이 앞에 붙지 않는다.**

### Messages API vs Managed Agents
Messages API = 내가 턴과 도구 루프를 직접 구성 / Managed Agents = 상태 유지 세션과 영구 이벤트 기록을 갖춘 **관리형 인프라**.

## 6. 보안·신뢰 관련 기억할 것

- 프로젝트 설정의 **`allow` 규칙·`additionalDirectories`·`env`·훅·프로젝트 스킬·`.mcp.json` 서버**는 워크스페이스 **신뢰 수락 후**에 적용된다. `deny`/`ask`는 신뢰 전에도 적용
- 신뢰 대화상자는 **대화형 세션에서만** 뜬다 (`claude -p`, SDK 세션은 안 뜸)
- 권한 규칙은 **모델이 아니라 Claude Code가 강제**한다
- Claude Code on the web은 설정 파일의 `bypassPermissions`/`dontAsk`를 **무시**한다
- `bypassPermissions`는 root/sudo에서 거부되고, `--restricted` 세션에서도 거부된다
- 외부 콘텐츠를 가져오는 MCP 서버는 **프롬프트 인젝션** 경로다
- 자격증명은 `.mcp.json`에 직접 쓰지 말고 환경변수 확장 또는 `headersHelper`로

## 7. 시험 전 자가 점검 질문

1. `.claude/settings.json`에 `bypassPermissions`를 넣으면 왜 적용되지 않는가?
2. `deny: Bash(aws *)`와 `allow: Bash(aws s3 ls)`가 같이 있으면 어떻게 되는가?
3. `/compact` 이후에도 살아남는 지시는 무엇이고, 사라지는 것은 무엇인가?
4. MCP 서버를 팀과 공유하려면 어떤 스코프를 쓰고 어떤 파일이 생기는가?
5. 도구 20개가 있고 선택이 자꾸 틀린다. 도구 설계를 어떻게 고치는가?
6. 서브에이전트가 CLAUDE.md는 보는데 메인 대화 히스토리는 못 보는 이유는?
7. 프롬프트 캐시가 계속 미스 난다. 브레이크포인트를 어디로 옮겨야 하는가?
8. `tool_choice: any`를 썼더니 설명 문장이 사라졌다. 왜인가?
9. 컨텍스트 편집으로 도구 결과를 지웠는데 캐시 히트가 사라졌다. 어떤 옵션으로 완화하는가?
10. "매 파일 편집 후 포매터 실행"을 어떤 훅 이벤트로 구현하는가?
