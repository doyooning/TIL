# D5. 컨텍스트 관리 & 신뢰성 (15%)

핵심 명제: **컨텍스트는 수익 체감이 있는 유한 자원이고, 관련 없는 내용은 모델의 집중력을 떨어뜨린다.** 그래서 "무엇을 넣을지"보다 "무엇을 빼고 어디에 오프로드할지"가 설계 문제가 된다.

## 1. 컨텍스트 윈도우를 채우는 것들

세션 시작 시 자동으로 들어오는 것:

| 항목 | 설명 |
| --- | --- |
| 시스템 프롬프트 | 행동·도구 사용·응답 형식 지침. 항상 첫 번째 |
| auto memory (`MEMORY.md`) | 처음 200줄 또는 25KB |
| 환경 정보 | 작업 디렉터리·플랫폼·셸·OS·git 여부. git 브랜치/상태/최근 커밋은 시스템 프롬프트 맨 끝 별도 블록 |
| CLAUDE.md 계층 + 범위 없는 rules | 시스템 프롬프트 **뒤의 사용자 메시지**로 전달됨 |
| MCP 도구 | 기본은 이름만(deferred), 스키마는 tool search로 필요 시 로드 |
| 스킬 설명 | 짧은 요약만. 본문은 호출 시 로드 |
| 내장 도구 스키마 | 매 요청 |
| 출력 스타일 / `--append-system-prompt` | 설정했다면 |

작업 중 누적되는 것: 파일 읽기 결과, 도구 입력/출력, 경로 스코프 규칙, 훅이 추가한 컨텍스트, 대화 히스토리.

> **CLAUDE.md가 시스템 프롬프트가 아니라 사용자 메시지로 전달된다**는 점이 "왜 엄격히 지켜지지 않는가"의 이유다. 시스템 프롬프트 레벨에 넣으려면 `--append-system-prompt`.

### 확인 명령
- `/context` — 카테고리별 실시간 사용량 + 최적화 제안 + 로드된 메모리 파일 목록
- `/memory` — 메모리 파일 열기/편집
- `/status` — 로드된 설정 파일

## 2. 압축(Compaction)

컨텍스트 한계에 가까워지면 **자동으로 대화를 요약**한다. 세션이 끝나지 않는다.

### 압축 후 무엇이 남는가 (시험 빈출)

| 메커니즘 | 압축 후 |
| --- | --- |
| 시스템 프롬프트, 출력 스타일 | 그대로 유지 |
| 프로젝트 루트 CLAUDE.md, 범위 없는 rules | **디스크에서 재주입** |
| auto memory | **디스크에서 재주입** |
| plan mode에서 작성한 계획 | **디스크에서 재주입** |
| `paths:` 프론트매터가 있는 rules | 매칭 파일을 읽을 때 다시 로드 |
| 하위 디렉터리의 중첩 CLAUDE.md | 해당 디렉터리 파일을 읽을 때 다시 로드 |
| Claude가 읽거나 편집한 파일 | **최근 수정 순으로 최대 5개**를 다시 읽음 |
| 호출했던 스킬 본문 | 재주입. **스킬당 5,000토큰 / 전체 25,000토큰** 상한, 오래된 것부터 제거 |
| 훅이 추가했던 컨텍스트 | 나머지 대화와 함께 요약됨 |
| `compact` 소스에 매칭되는 `SessionStart` 훅 | 실행되어 출력이 압축된 컨텍스트에 추가됨 |

> **대화 중에만 준 지시는 사라진다.** 영구적 규칙은 CLAUDE.md에 넣어야 한다.
> 스킬 본문은 잘릴 때 **앞부분이 보존**되므로 중요한 지시를 SKILL.md 위쪽에 둔다.

### 컨텍스트가 찰 때 할 수 있는 일

| 방법 | 효과 |
| --- | --- |
| `/compact <지시>` | 요약에 무엇을 남길지 직접 지정 (예: `/compact focus on the auth bug fix`) |
| `/rewind` → Summarize from/up to here | 대화의 **일부만** 압축 |
| `/autocompact 500k` | 자동 압축이 실행되는 임계치 조정 |
| `/clear` | 무관한 작업으로 전환할 때 대화 초기화 |
| 서브에이전트에 위임 | 대용량 읽기를 서브에이전트 컨텍스트에 가둔다 |
| 확장 컨텍스트 | Fable 계열, Sonnet 5, Opus 4.6+, Sonnet 4.6은 **1M 토큰** 윈도우 지원(Sonnet 5는 기본 1M, `[1m]` 변형 없음) |

압축 요약 요청은 세션의 extended thinking 설정을 상속한다.

### CLAUDE.md로 압축 지시하기

```markdown
# Summary instructions

When summarizing this conversation, always preserve:
- The current task objective and acceptance criteria
- File paths that have been read or modified
- Test results and error messages
- Decisions made and the reasoning behind them
```

`PreCompact` 훅으로 압축 전에 전체 트랜스크립트를 아카이브할 수도 있다.

## 3. 컨텍스트 편집 (Context Editing, API)

서버 측에서 특정 콘텐츠를 선택적으로 지운다. 베타 헤더 `context-management-2025-06-27`.

> 대부분의 경우 **서버 측 압축(compaction)** 이 기본 전략이고, 컨텍스트 편집은 **무엇을 지울지 세밀히 제어**해야 할 때 쓴다.

### 전략

| 전략 | 대상 | 용도 |
| --- | --- | --- |
| `clear_tool_uses_20250919` | 오래된 도구 결과 | 도구 사용이 많은 에이전트 워크플로 |
| `clear_thinking_20251015` | thinking 블록 | 확장 사고 사용 시 추론 연속성과 컨텍스트 절약의 균형 |

### 도구 결과 지우기 설정 옵션

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `trigger` | 100,000 입력 토큰 | 전략 활성화 임계값. `input_tokens` 또는 `tool_uses`로 지정 |
| `keep` | 최근 3개 도구 사용 | 지운 뒤 유지할 최근 도구 사용/결과 쌍의 수 |
| `clear_at_least` | 없음 | 최소 이만큼 지워지지 않으면 전략을 적용하지 않음 (캐시 무효화 대비) |
| `exclude_tools` | 없음 | 절대 지우지 않을 도구 이름 목록 |
| `clear_tool_inputs` | `false` | 도구 호출 파라미터까지 지울지 여부 (기본은 결과만 지움) |

- 지워진 결과는 **제거되었음을 알리는 플레이스홀더 텍스트**로 대체된다
- **서버 측에서 적용**되므로 클라이언트는 원본 대화 기록을 그대로 유지하면 된다(동기화 불필요)
- 응답의 `context_management.applied_edits`로 적용 내역과 통계를 확인

### 프롬프트 캐싱과의 상호작용
- **도구 결과 지우기**: 캐시된 접두사를 **무효화**한다 → `clear_at_least`로 캐시를 깨뜨릴 만큼 충분한 토큰이 지워질 때만 동작하게 한다
- **사고 블록 지우기**: 사고 블록을 **유지하면 캐시 보존**, **지우면 그 지점부터 캐시 무효화**

### 메모리 도구와의 조합 (핵심 패턴)
지우기 임계값에 가까워지면 Claude가 자동 경고를 받는다. 그 시점에 중요한 정보를 **메모리 파일에 기록**해 두면,
- 도구 결과가 지워져도 정보는 남고
- 필요할 때 메모리 파일을 조회해 다시 가져올 수 있으며
- 컨텍스트 한도를 초과했을 장기 워크플로가 가능해진다

## 4. 프롬프트 캐싱

| 항목 | 값 |
| --- | --- |
| 최대 캐시 브레이크포인트 | **4개** |
| 기본 TTL | **5분** |
| 확장 TTL | **1시간** (추가 비용) |
| 룩백 윈도우 | 20블록 |
| 최소 캐시 가능 토큰 | Fable 5.1 / Mythos 5.1 / Opus 5 = **512**, Sonnet 5 = **1,024**, Haiku 4.5 = **4,096** |

### 가격

| 작업 | 배수 |
| --- | --- |
| 캐시 쓰기 (5분) | 기본 입력의 **1.25배** |
| 캐시 쓰기 (1시간) | 기본 입력의 **2배** |
| 캐시 읽기 | 기본 입력의 **0.1배** |

### 캐시 계층과 무효화
캐시는 **tools → system → messages** 순으로 구축된다. 상위가 바뀌면 하위가 전부 무효화된다.

| 변경 | tools | system | messages |
| --- | --- | --- | --- |
| 도구 정의 수정 | 무효 | 무효 | 무효 |
| 웹 검색/인용 토글 | 유지 | 무효 | 무효 |
| `tool_choice` 변경 | 유지 | 유지 | 무효 |
| 이미지 추가/제거 | 유지 | 유지 | 무효 |

### 사용 지표
```
총 입력 토큰 = cache_read_input_tokens + cache_creation_input_tokens + input_tokens
```
`input_tokens`는 **마지막 캐시 브레이크포인트 이후의 토큰**만 센다.

### 모범 사례
- 정적 콘텐츠(시스템 지침·컨텍스트·도구)를 프롬프트 **앞쪽**에 배치하고 그 끝에 브레이크포인트
- 멀티턴 대화는 자동 캐싱 사용, 변경 빈도가 다른 섹션은 명시적 브레이크포인트
- 타임스탬프처럼 매 요청 바뀌는 콘텐츠 앞에는 브레이크포인트를 두지 않는다
- 20블록 이상 긴 대화에서 브레이크포인트가 없으면 룩백 윈도우를 벗어난다
- 캐시 사전 워밍: `max_tokens=0` 요청(단 스트리밍/extended thinking/structured output/특정 `tool_choice`와 함께 쓰면 거부됨)
- **thinking 블록은 단독으로 캐싱할 수 없다**

Claude Code / Agent SDK에서는 시스템 프롬프트·도구 정의·CLAUDE.md처럼 턴마다 동일한 내용이 **자동으로 캐싱**된다.

## 5. 신뢰성 설계 체크리스트

| 위험 | 대응 |
| --- | --- |
| 무한 루프·폭주 비용 | `max_turns`, `max_budget_usd` (서브에이전트 비용 포함) |
| 긴 세션에서 지시 유실 | 지시를 CLAUDE.md/rules로, 절차는 스킬로, 강제는 훅으로 |
| 대용량 도구 출력 | 서브에이전트 위임, MCP 출력 제한(`MAX_MCP_OUTPUT_TOKENS`), 컨텍스트 편집 |
| 파괴적 행동 | `permissions.deny`, `PreToolUse` 훅(exit 2), critical path 보호 |
| 프롬프트 인젝션 | 신뢰된 MCP 서버만, 외부 콘텐츠를 지시가 아닌 데이터로 취급, 권한으로 제한 |
| 잘못된 형식의 출력 | `output_config.format`, `strict: true` |
| 모델 가용성 | `fallbackModel` 체인 |
| 상태 유실 | 메모리 도구 / 노트 파일로 오프로드, 세션 resume·fork |
